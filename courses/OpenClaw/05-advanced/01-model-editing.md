# 第十四讲：Model Editing 技术

> 对应视频：第十一讲 - 浅谈 Model Editing

## 本章概要

本章将介绍模型编辑（Model Editing）技术，这是一种在不重新训练的情况下修改大语言模型知识的方法。

---

## 1. 什么是 Model Editing？

### 1.1 问题背景

```
模型知识更新的挑战
────────────────────────────────────────────────────────

传统方法：
修改模型知识 → 重新训练 → 成本极高

问题：
• 训练成本：数百万美元
• 时间成本：数周甚至数月
• 数据收集：需要大量新数据
• 可能导致灾难性遗忘

理想方案：
精确定位 → 局部修改 → 低成本更新
```

### 1.2 Model Editing 定义

**Model Editing**：在不完全重新训练的情况下，精确修改模型中的特定知识。

```
Model Editing 目标
────────────────────────────────────────────────────────

┌─────────────────────────────────────────────────────┐
│                                                     │
│  原始模型: "埃菲尔铁塔在伦敦"                        │
│       ↓                                             │
│  Model Editing                                      │
│       ↓                                             │
│  编辑后模型: "埃菲尔铁塔在巴黎"                      │
│                                                     │
│  同时保持：                                         │
│  • 其他知识不变                                     │
│  • 模型能力不变                                     │
│  • 不需要重新训练                                   │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## 2. 核心方法

### 2.1 ROME (Rank-One Model Editing)

```
ROME 原理
────────────────────────────────────────────────────────

核心思想：知识存储在 MLP 层，通过修改特定层的权重来更新知识

步骤：
1. 定位：找到存储目标知识的层
2. 计算：计算需要修改的向量
3. 注入：用 rank-one 更新修改权重

公式：
W' = W + uv^T

其中：
• W: 原始权重
• u, v: 计算得到的向量
• W': 编辑后的权重
```

### 2.2 MEMIT (Mass-Editing Memory in a Transformer)

```
MEMIT 原理
────────────────────────────────────────────────────────

ROME 的扩展：支持批量编辑多个知识

优势：
• 可以同时编辑数千条知识
• 保持编辑之间的一致性
• 更好的泛化能力

算法：
1. 收集要编辑的知识集合
2. 计算每条知识的定位向量
3. 批量更新多个层
```

### 2.3 对比

| 方法 | 编辑数量 | 成功率 | 副作用 |
|------|---------|--------|--------|
| **Fine-tuning** | 任意 | 低 | 大（灾难性遗忘）|
| **ROME** | 单条 | 高 | 小 |
| **MEMIT** | 批量 | 高 | 小 |

## 3. 实现原理

### 3.1 知识定位

```
知识存储位置
────────────────────────────────────────────────────────

研究发现：大部分事实知识存储在 MLP 层

Transformer 结构：
┌─────────────────────────────────────────────────────┐
│ Layer N                                             │
│  ┌──────────────┐                                  │
│  │ Attention    │ ← 关系建模                        │
│  └──────────────┘                                  │
│  ┌──────────────┐                                  │
│  │ MLP (FFN)    │ ← 事实知识存储 ← 编辑目标        │
│  └──────────────┘                                  │
└─────────────────────────────────────────────────────┘

定位步骤：
1. 分析各层对目标输出的贡献
2. 确定关键层（通常在中间层）
3. 定位具体的神经元
```

### 3.2 编辑过程

```
ROME 编辑过程
────────────────────────────────────────────────────────

输入：
• 主题 s: "埃菲尔铁塔"
• 关系 r: "位于"
• 原值 o: "伦敦"
• 新值 o*: "巴黎"

步骤：
1. 提取主题表示
   h = f(s)  # 主题的隐藏状态

2. 计算键值对
   k = W_k · h  # 键向量
   v* = g(o*)   # 新值向量

3. 构建更新
   W' = W + (v* - v) · k^T / (k^T · k)

4. 应用更新
   用 W' 替换 W
```

## 4. 应用场景

### 4.1 知识更新

```
场景：更新过时或错误的知识
────────────────────────────────────────────────────────

例子：
• 公司 CEO 更换
• 政治领导人变更
• 技术版本更新
• 事实纠正

优势：
• 快速响应
• 低成本
• 精确控制
```

### 4.2 个性化定制

```
场景：为特定用户/组织定制模型
────────────────────────────────────────────────────────

例子：
• 企业专属知识注入
• 用户偏好设置
• 领域知识增强

实现：
为每个用户/组织维护一个"编辑集"
```

### 4.3 安全对齐

```
场景：移除有害知识
────────────────────────────────────────────────────────

例子：
• 移除危险知识
• 纠正偏见
• 消除幻觉源

挑战：
• 识别所有需要编辑的知识
• 避免过度编辑影响能力
```

## 5. 代码示例

### 5.1 使用 EasyEdit 库

```python
# 安装 EasyEdit
# pip install easyedit

from easyedit import ROMEHyperParams, apply_rome_to_model
from easyedit import MemitHyperParams, apply_memit_to_model

# ROME 编辑示例
hparams = ROMEHyperParams(
    layers = [5],           # 编辑的层
    norm_scope = "model.norm",
    vn_layers = [5],
)

# 编辑单条知识
model, _ = apply_rome_to_model(
    model,
    tok,
    requests=[
        {
            "prompt": "埃菲尔铁塔位于{}",
            "subject": "埃菲尔铁塔",
            "target_new": {"str": "巴黎"}
        }
    ],
    hparams=hparams
)

# MEMIT 批量编辑
hparams = MemitHyperParams(
    layers = [5, 7, 9],
    stats_dir = "./stats"
)

requests = [
    {"prompt": "{}的首都是", "subject": "法国", "target_new": {"str": "巴黎"}},
    {"prompt": "{}的首都是", "subject": "德国", "target_new": {"str": "柏林"}},
    {"prompt": "{}的首都是", "subject": "意大利", "target_new": {"str": "罗马"}},
]

model, _ = apply_memit_to_model(
    model,
    tok,
    requests=requests,
    hparams=hparams
)
```

### 5.2 验证编辑效果

```python
def verify_edit(model, tok, prompt, expected):
    """验证编辑是否成功"""
    inputs = tok(prompt, return_tensors="pt")
    outputs = model.generate(**inputs, max_length=50)
    response = tok.decode(outputs[0], skip_special_tokens=True)

    print(f"Prompt: {prompt}")
    print(f"Response: {response}")
    print(f"Expected: {expected}")
    print(f"Match: {expected in response}")

# 验证
verify_edit(model, tok, "埃菲尔铁塔位于哪里？", "巴黎")
```

## 6. 局限性与挑战

### 6.1 技术局限

```
当前挑战
────────────────────────────────────────────────────────

1. 知识纠缠
   • 修改一条知识可能影响相关知识
   • 例如：修改"法国首都"可能影响"巴黎在哪个国家"

2. 泛化问题
   • 编辑后模型可能无法泛化到所有表述方式
   • 例如：编辑"埃菲尔铁塔在巴黎"，但"巴黎有埃菲尔铁塔"可能不变

3. 长期稳定性
   • 编辑的效果可能随时间退化
   • 多次编辑可能累积误差

4. 编辑检测
   • 难以自动检测哪些知识需要编辑
   • 需要人工审核
```

### 6.2 实践建议

```
最佳实践
────────────────────────────────────────────────────────

1. 批量编辑优于多次单条编辑
   使用 MEMIT 而非多次 ROME

2. 验证编辑效果
   • 直接测试：编辑的提示词
   • 间接测试：相关提示词
   • 能力测试：确保模型能力未受损

3. 保留原始模型
   编辑是不可逆的，保留备份

4. 增量编辑
   记录所有编辑，便于追溯和回滚
```

## 关键要点总结

1. **Model Editing**：不重新训练的情况下修改模型知识
2. **ROME**：单条知识编辑，rank-one 更新
3. **MEMIT**：批量知识编辑，效率更高
4. **应用场景**：知识更新、个性化定制、安全对齐
5. **挑战**：知识纠缠、泛化问题、长期稳定性
