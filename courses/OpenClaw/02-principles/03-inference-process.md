# 第六讲：大语言模型推理与评估

> 对应视频：第九讲、第十讲 - 大型语言模型的推理过程 / 大型语言模型评估

## 本章概要

本章将介绍大语言模型的推理过程和评估方法，帮助你理解模型如何生成输出以及如何衡量模型质量。

---

## 1. 推理过程概述

### 1.1 什么是推理？

**推理（Inference）**：使用训练好的模型生成输出的过程。

```
推理流程
────────────────────────────────────────────────────────

用户输入: "解释什么是机器学习"
    │
    ↓
┌─────────────────┐
│   Tokenization  │  文本 → Token IDs
└────────┬────────┘
         │
         ↓
┌─────────────────┐
│   Embedding     │  Token IDs → 向量
└────────┬────────┘
         │
         ↓
┌─────────────────┐
│   Transformer   │  多层处理
│   Layers × N    │
└────────┬────────┘
         │
         ↓
┌─────────────────┐
│   Logits        │  词表大小的向量
└────────┬────────┘
         │
         ↓
┌─────────────────┐
│   Sampling      │  选择下一个 Token
└────────┬────────┘
         │
         ↓
    重复直到结束
         │
         ↓
┌─────────────────┐
│   Detokenize    │  Token IDs → 文本
└─────────────────┘
```

### 1.2 自回归生成

```
自回归生成过程
────────────────────────────────────────────────────────

Step 1:
输入: [BOS] 解释
输出: "什么"

Step 2:
输入: [BOS] 解释什么
输出: "是"

Step 3:
输入: [BOS] 解释什么是
输出: "机器"

Step 4:
输入: [BOS] 解释什么是机器
输出: "学习"

...

直到生成 [EOS] 或达到最大长度
```

## 2. 采样策略

### 2.1 Greedy Search

```
贪心搜索
────────────────────────────────────────────────────────

策略：每次选择概率最高的 Token

┌─────────────────────────────────────────────────────┐
│ Logits: [0.1, 0.3, 0.5, 0.05, 0.05]                │
│                     ↓                               │
│                 max = 0.5                           │
│                     ↓                               │
│               选择 Token 2                          │
└─────────────────────────────────────────────────────┘

优点：确定性输出，可复现
缺点：可能陷入重复，缺乏多样性

示例：
输入: "从前有座"
输出: "山，山上有座庙，庙里有个老和尚..."
                    ↑ 可能重复
```

### 2.2 Temperature Sampling

```
温度采样
────────────────────────────────────────────────────────

公式：P'(x) = softmax(logits / T)

温度 T 的效果：
• T = 1: 原始分布
• T < 1: 更确定（分布更尖锐）
• T > 1: 更随机（分布更平坦）

┌─────────────────────────────────────────────────────┐
│                                                     │
│  T = 0.5 (确定性)     T = 1.0 (正常)    T = 2.0 (随机)│
│                                                     │
│  ████████████         ██████           ████         │
│  ████████████         ██████           ████         │
│  ██                   ██████           ████         │
│  █                    ██████           ████         │
│  █                    █                ████         │
│                                                     │
└─────────────────────────────────────────────────────┘

推荐值：
• 代码生成: 0.2 - 0.5
• 创意写作: 0.7 - 1.0
• 头脑风暴: 1.0 - 1.5
```

### 2.3 Top-K Sampling

```
Top-K 采样
────────────────────────────────────────────────────────

策略：只从概率最高的 K 个 Token 中采样

┌─────────────────────────────────────────────────────┐
│ 原始概率分布:                                        │
│ A: 0.4, B: 0.3, C: 0.2, D: 0.05, E: 0.05           │
│                                                     │
│ K = 3:                                              │
│ 只考虑 A, B, C                                      │
│ 重新归一化: A: 0.44, B: 0.33, C: 0.22              │
│                                                     │
│ 从 {A, B, C} 中按概率采样                           │
└─────────────────────────────────────────────────────┘

优点：避免选择概率极低的 Token
缺点：K 值难以确定
```

### 2.4 Top-P (Nucleus) Sampling

```
Top-P 采样
────────────────────────────────────────────────────────

策略：从累积概率达到 P 的最小 Token 集合中采样

┌─────────────────────────────────────────────────────┐
│ 概率排序:                                            │
│ A: 0.4, B: 0.3, C: 0.15, D: 0.1, E: 0.05           │
│                                                     │
│ P = 0.9:                                            │
│ A + B + C = 0.85 < 0.9                              │
│ A + B + C + D = 0.95 > 0.9 ✓                        │
│                                                     │
│ 采样集合: {A, B, C, D}                              │
└─────────────────────────────────────────────────────┘

优点：自适应调整候选数量
推荐值：P = 0.9 ~ 0.95
```

### 2.5 组合策略

```
常用组合
────────────────────────────────────────────────────────

推荐配置 1（通用）:
Temperature = 0.7
Top-P = 0.9

推荐配置 2（确定性任务）:
Temperature = 0.3
Top-P = 0.95

推荐配置 3（创意任务）:
Temperature = 1.0
Top-P = 0.9

代码示例：
```python
output = model.generate(
    input_ids,
    max_length=100,
    temperature=0.7,
    top_p=0.9,
    do_sample=True
)
```
```

### 2.6 其他解码技巧

```
进阶解码策略
────────────────────────────────────────────────────────

1. Beam Search
   • 保留多个候选序列
   • 选择整体概率最高的

2. Repetition Penalty
   • 惩罚重复的 Token
   • penalty = 1.0 ~ 1.2

3. Length Penalty
   • 鼓励/惩罚长输出

4. Frequency Penalty
   • 惩罚高频词

5. Presence Penalty
   • 惩罚已出现的词
```

## 3. 推理优化

### 3.1 KV Cache

```
KV Cache 优化
────────────────────────────────────────────────────────

问题：自回归生成时重复计算

无 Cache:
每次生成都要重新计算所有之前的 K, V

有 Cache:
保存之前计算的 K, V，只计算新 Token

┌─────────────────────────────────────────────────────┐
│                                                     │
│  Step 1: 计算 K₁, V₁, 缓存                          │
│  Step 2: 计算 K₂, V₂, 缓存，复用 K₁, V₁            │
│  Step 3: 计算 K₃, V₃, 缓存，复用 K₁, V₁, K₂, V₂   │
│  ...                                                │
│                                                     │
└─────────────────────────────────────────────────────┘

复杂度：O(n²) → O(n) (每步)
```

### 3.2 批处理推理

```
批处理 (Batching)
────────────────────────────────────────────────────────

同时处理多个请求，提高 GPU 利用率

┌─────────────────────────────────────────────────────┐
│                                                     │
│  请求 1: "你好"                                     │
│  请求 2: "Hello"                                    │
│ 请求 3: "こんにちは"                                │
│         │                                           │
│         ↓                                           │
│  ┌─────────────────┐                               │
│  │   Batch 处理    │                               │
│  └─────────────────┘                               │
│         │                                           │
│         ↓                                           │
│  响应 1, 响应 2, 响应 3                             │
│                                                     │
└─────────────────────────────────────────────────────┘

注意：需要 Padding 到相同长度
```

### 3.3 量化推理

```
量化 (Quantization)
────────────────────────────────────────────────────────

降低精度以减少显存和加速推理

FP16 (16 bit) → INT8 (8 bit) → INT4 (4 bit)

┌─────────────────────────────────────────────────────┐
│                                                     │
│  FP16 模型: 70B 参数 × 2 bytes = 140 GB             │
│  INT8 模型: 70B 参数 × 1 byte = 70 GB               │
│  INT4 模型: 70B 参数 × 0.5 byte = 35 GB             │
│                                                     │
│  精度损失：通常可接受                               │
│                                                     │
└─────────────────────────────────────────────────────┘

常用工具：
• bitsandbytes
• GPTQ
• AWQ
```

### 4.3 评估指标

```
常用评估指标
────────────────────────────────────────────────────────

1. 准确率 (Accuracy)
   正确数 / 总数

2. BLEU Score
   • 机器翻译常用
   • 比较 n-gram 重叠

3. ROUGE Score
   • 摘要任务常用
   • ROUGE-1, ROUGE-2, ROUGE-L

4. Perplexity (困惑度)
   • 语言模型质量
   • 越低越好

5. Pass@k
   • 代码生成
   • k 个样本中至少一个正确

6. 人工评估
   • 流畅性、相关性、准确性
   • 最可靠但成本高
```
