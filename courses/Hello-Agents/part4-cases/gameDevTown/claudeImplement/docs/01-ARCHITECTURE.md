# 游戏小镇 (Game Dev Town) - 技术架构文档

## 1. 项目概述

### 1.1 项目定位
游戏小镇是一个展示 AI Agent 协作能力的演示平台。通过模拟游戏开发团队会议场景，展示多个 AI Agent 如何扮演不同角色（制作人、程序员、策划、美术）进行协作讨论。

### 1.2 核心价值
- **教育演示**：直观展示 Multi-Agent 系统的工作原理
- **技术参考**：提供完整的 AI Agent 协作系统实现范例
- **可扩展性**：模块化设计便于扩展新的 Agent 和场景

### 1.3 技术栈概览

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | HTML5 + CSS3 + JavaScript ES6+ | 原生实现，无框架依赖 |
| 后端 | Python 3.10+ / FastAPI | 高性能异步 Web 框架 |
| 通信 | REST API + WebSocket | 支持实时双向通信 |
| LLM | MiniMax API (Anthropic 兼容) | 大语言模型服务 |

### 2.2 架构层次说明

#### 2.2.1 前端层 (Frontend)
采用原生 JavaScript 模块化设计，无框架依赖，便于理解和部署。

| 模块 | 职责 |
|------|------|
| `app.js` | 主应用逻辑，初始化组件，管理全局状态 |
| `api.js` | 封装 REST API 和 WebSocket 通信 |
| `chat.js` | 聊天消息渲染，支持打字动画 |
| `characters.js` | Agent 角色卡片状态管理 |
| `dashboard.js` | 项目进度和任务看板 |

#### 2.2.2 API 层
基于 FastAPI 实现的高性能异步 API。

| 模块 | 职责 |
|------|------|
| `routes.py` | RESTful API 端点定义 |
| `websocket.py` | WebSocket 连接管理和消息处理 |

#### 2.2.3 服务层
提供 LLM 服务封装。

| 模块 | 职责 |
|------|------|
| `llm.py` | MiniMax API 调用封装，支持流式响应和降级模式 |

#### 2.2.4 会议系统
管理会议流程和场景模板。

| 模块 | 职责 |
|------|------|
| `orchestrator.py` | 会议编排，控制 Agent 发言顺序，广播消息 |
| `templates.py` | 预定义的会议场景和对话模板 |

#### 2.2.5 Agent 层
实现角色扮演的 AI Agent。

| 模块 | 职责 |
|------|------|
| `base.py` | 基础 Agent 抽象类，定义通用接口 |
| `producer.py` | 制作人 Agent，项目管理视角 |
| `developer.py` | 程序员 Agent，技术实现视角 |
| `designer.py` | 策划 Agent，玩法设计视角 |
| `artist.py` | 美术 Agent，视觉表现视角 |

#### 2.2.6 核心系统层
提供 Agent 的底层能力支持。

| 模块 | 职责 |
|------|------|
| `memory.py` | 短期/长期记忆管理 |
| `decision.py` | 基于角色特征的决策分析 |
| `task.py` | 项目任务生命周期管理 |
| `conversation.py` | 会议对话流程管理 |

### 3.2 WebSocket 消息类型

| 消息类型 | 方向 | 说明 |
|----------|------|------|
| `connected` | Server → Client | 连接成功，返回初始数据 |
| `start_meeting` | Client → Server | 请求开始会议 |
| `meeting_started` | Server → Client | 会议已开始通知 |
| `run_scenario` | Client → Server | 运行场景（后台任务模式） |
| `run_discussion` | Client → Server | 请求运行讨论 |
| `agent_status` | Server → Client | Agent 状态更新（发言中/情绪） |
| `new_message` | Server → Client | 新消息到达 |
| `send_message` | Client → Server | 用户发送消息 |
| `end_meeting` | Client → Server | 请求结束会议（可中断） |
| `meeting_ended` | Server → Client | 会议结束，返回总结（含 task_stats） |
| `status_update` | Server → Client | 项目状态更新 |

### 3.3 后台任务与中断机制

为支持实时中断会议，场景运行采用后台任务模式：

```
WebSocket 消息循环                    后台任务
       │                               │
       │  run_scenario 请求            │
       ├──────────────────────────────►│
       │  asyncio.create_task()        │
       │                               │
       │  ◄── 立即返回 ──►             │
       │                               │
       │                               │── 运行讨论循环
       │                               │── 检查 _should_stop
       │                               │── 广播消息
       │                               │
       │  end_meeting 请求             │
       ├───► task.cancel() ───────────►│
       │                               │── asyncio.CancelledError
       │                               │── 清理资源
       │  ◄── meeting_ended ───────────┤
       │                               │
```

**关键实现**：
```python
# websocket.py
current_scenario_task = None  # 全局任务引用

async def handle_run_scenario(websocket, data):
    global current_scenario_task

    async def run_discussion():
        try:
            await orchestrator.run_interactive_discussion(rounds=rounds)
            # 自动结束
            if orchestrator.meeting_active:
                result = await orchestrator.end_meeting()
                await manager.broadcast({"type": "meeting_ended", "data": result})
        except asyncio.CancelledError:
            print("场景任务被取消")

    current_scenario_task = asyncio.create_task(run_discussion())

async def handle_end_meeting(websocket, data):
    global current_scenario_task

    # 取消正在运行的任务
    if current_scenario_task and not current_scenario_task.done():
        current_scenario_task.cancel()

    result = await orchestrator.end_meeting()
    await manager.broadcast({"type": "meeting_ended", "data": result})
```

## 6. 扩展设计

### 6.1 添加新 Agent

1. 在 `app/agents/` 创建新的 Agent 类，继承 `BaseAgent`
2. 实现 `respond_to_agenda()` 和 `react_to_message()` 方法
3. 在 `config.py` 的 `AGENT_ROLES` 添加角色配置
4. 在 `agents/__init__.py` 注册到工厂函数

### 6.2 添加新场景

1. 在 `meeting/templates.py` 的 `SCENARIO_PROMPTS` 添加场景定义
2. 在前端 `index.html` 的场景选择器添加选项

### 6.3 接入其他 LLM

1. 在 `services/` 创建新的 LLM 服务类
2. 实现与现有 `LLMService` 相同的接口
3. 在 `config.py` 添加配置选项

## 7. 性能考量

### 7.1 并发处理
- FastAPI 原生支持异步，可高效处理并发请求
- WebSocket 连接使用 `ConnectionManager` 统一管理

### 7.2 内存管理
- Agent 记忆系统使用 `deque` 限制大小，防止内存溢出
- 会议结束后清理临时状态

### 7.3 响应优化
- LLM 调用支持流式响应，提升用户体验
- 前端消息渲染使用动画，避免页面卡顿

### 8.1 API 安全
- 敏感配置通过环境变量管理
- CORS 配置限制允许的源
