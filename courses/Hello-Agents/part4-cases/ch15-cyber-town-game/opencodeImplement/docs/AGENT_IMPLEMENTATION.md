# Agent 实现规划

本文档详细介绍赛博小镇中 Agent 系统的实现规划。

## 实现步骤

### 第一阶段：基础框架 (1-2天)

#### 1.1 创建角色类

**目标**: 定义角色的基本属性和状态

```
任务清单:
✓ 定义 Character 类
  - id: 唯一标识
  - name: 姓名
  - age: 年龄
  - personality: 性格对象
  - mood/energy/hunger/social: 状态值
  - current_location: 当前位置
  - relationships: 关系字典
  - memories: 记忆列表
  - goals: 目标列表

✓ 实现基本状态管理
  - update_state(): 更新状态
  - get_state(): 获取状态
  - check_needs(): 检查需求
```

#### 1.2 创建世界系统

**目标**: 管理游戏世界的时间和地点

```
任务清单:
✓ 实现时间系统
  - TimeSystem 类
  - current_time: 当前时间
  - time_scale: 时间速度
  - update(): 更新时间
  - get_time_of_day(): 获取时段

✓ 创建基础地点
  - Location 类
  - 地点列表: 酒馆、咖啡馆、公园、商店、住宅
  - can_accommodate(): 检查容量
  - get_social_opportunity(): 社交机会
```

#### 1.3 实现主循环

```
任务清单:
✓ 实现游戏主循环
  - tick(): 时间推进
  - process_agents(): 处理所有Agent
  - update_world(): 更新世界状态
  - broadcast_state(): 广播状态
```

### 第二阶段：行为系统 (2-3天)

#### 2.1 实现决策系统

**目标**: Agent 能够自主决定下一步行动

```
决策流程:
┌─────────────────────────────────────────────────────────────┐
│                    行为决策流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  输入: character, world_state, nearby_agents                │
│                                                             │
│  1. 评估当前状态                                            │
│     ├── 检查需求满足度 (饥饿/能量/社交)                       │
│     ├── 检查当前目标进度                                     │
│     └── 检查当前位置是否合适                                 │
│                                                             │
│  2. 检索相关记忆                                            │
│     ├── 检索与当前情况相关的记忆                              │
│     └── 检索与其他角色的互动经验                              │
│                                                             │
│  3. 生成候选行动                                            │
│     ├── 移动到其他地点                                       │
│     ├── 与附近角色对话                                       │
│     ├── 休息/进食                                           │
│     └── 等待/观察                                           │
│                                                             │
│  4. 评估行动得分                                            │
│     ├── 需求满足度权重                                       │
│     ├── 目标相关性权重                                       │
│     ├── 性格匹配度权重                                       │
│     ├── 社交影响权重                                         │
│     └── 记忆影响权重                                         │
│                                                             │
│  5. 选择最优行动                                            │
│     └── 返回得分最高的行动                                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 2.2 实现基础行为

**目标**: 实现角色可以执行的基本行为

```
行为类型:
┌─────────────────────────────────────────────────────────────┐
│                     基础行为列表                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  移动行为 (Movement)                                        │
│  ├── move_to(location): 移动到指定地点                        │
│  └── can_move_to(location): 检查是否可以移动                │
│                                                             │
│  生存行为 (Survival)                                        │
│  ├── eat(): 进食 (降低饥饿值)                                │

│                                                             │
│  社交行为 (Social)                                          │
│  ├── greet(character): 打招呼                               │
│  ├── talk(character, topic): 交谈                          │
│  └── interact(character, action): 互动                     │
│                                                             │
│  观察行为 (Observation)                                      │
│  └── observe(): 观察周围环境                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 2.3 实现需求系统

**目标**: 角色的需求影响行为决策

```
需求模型:
┌─────────────────────────────────────────────────────────────┐
│                      需求系统                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  饥饿需求 (Hunger)                                          │
│  - 范围: 0.0 - 1.0                                          │
│  - 0.0 = 不饿, 1.0 = 非常饿                                  │
│  - 增长: 每个tick增加 0.01                                   │
│  - 行为: 饥饿 > 0.7 时，寻找食物                             │
│                                                             │
│  能量需求 (Energy)                                          │
│  - 范围: 0.0 - 1.0                                          │
│  - 0.0 = 精疲力尽, 1.0 = 精力充沛                            │
│  - 消耗: 活动时减少能量                                       │
│  - 行为: 能量 < 0.3 时，寻找休息                            │
│                                                             │
│  社交需求 (Social)                                          │
│  - 范围: 0.0 - 1.0                                          │
│  - 0.0 = 极度孤独, 1.0 = 满足社交                           │
│  - 变化: 独处时增加，社交时减少                               │
│  - 行为: 社交 > 0.6 时，寻找社交机会                         │
│                                                             │
│  情绪 (Mood)                                                │
│  - 范围: -1.0 - 1.0                                         │
│  - -1.0 = 悲伤, 1.0 = 快乐                                  │
│  - 变化: 受事件和其他角色影响                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**目标**: 存储角色的经历

```
记忆结构:
┌─────────────────────────────────────────────────────────────┐
│                      Memory 类                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  属性:                                                      │
│  - event: str (事件描述)                                    │

│  - emotional_impact: float (情感影响 -1到1)                 │
│  - timestamp: datetime (时间戳)                            │
│  - associations: list (关联记忆)                           │
│  - access_count: int (访问次数)                            │
│                                                             │
│  方法:                                                      │
│  - decay(): 记忆衰减                                        │
│  - strengthen(): 加深记忆                                   │
│  - get_relevance(query): 计算相关性                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 3.2 实现记忆检索

**目标**: 检索与当前情况相关的记忆

```
检索流程:
┌─────────────────────────────────────────────────────────────┐
│                    记忆检索流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  输入: character, query, context                           │
│                                                             │
│  1. 关键词匹配                                              │
│     └── 从记忆库中找出包含关键词的记忆                         │
│                                                             │
│  2. 计算相关性                                              │
│     ├── 时间近度: 越近的记忆相关性越高                        │
│     ├── 重要性: 越重要的记忆相关性越高                         │
│     ├── 情感相关性: 与当前情绪相关的记忆                      │
│     └── 访问次数: 访问越多的记忆越容易被检索                   │
│                                                             │
│  3. 排序返回                                                │
│     └── 按相关性排序，返回 top-k                             │
│                                                             │
│  4. 访问计数                                                │
│     └── 增加记忆的访问次数                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 3.3 实现记忆衰减

**目标**: 模拟人类记忆随时间遗忘

```
衰减模型:
┌─────────────────────────────────────────────────────────────┐
│                    记忆衰减公式                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  decay_factor = e^(-age / decay_rate)                      │
│                                                             │
│  其中:                                                      │
│  - age: 记忆经过的时间                                       │
│  - decay_rate: 衰减率 (默认 24小时)                          │
│                                                             │
│  示例:                                                      │
│  - 1小时后: e^(-1/24) = 0.96                                │
│  - 6小时后: e^(-6/24) = 0.78                               │
│  - 24小时后: e^(-24/24) = 0.37                             │
│  - 48小时后: e^(-48/24) = 0.14                             │
│                                                             │
│  特殊规则:                                                  │
│  - 高重要性(>0.8)记忆衰减减半                                │
│  - 情感强烈(>0.7)记忆衰减减半                                │
│  - 每次访问增加 importance 0.1                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 代码实现顺序

建议按以下顺序实现代码:

1. `backend/config.py` - 配置类
2. `backend/agent/character.py` - 角色类
3. `backend/world/time.py` - 时间系统
4. `backend/world/location.py` - 地点系统
5. `backend/agent/memory.py` - 记忆系统
6. `backend/agent/behavior.py` - 行为系统
7. `backend/agent/decision.py` - 决策系统
8. `backend/social/relationship.py` - 关系系统
9. `backend/social/communication.py` - 对话系统
10. `backend/world/event.py` - 事件系统
11. `backend/llm/minimax.py` - LLM客户端
12. `backend/main.py` - FastAPI主程序
13. `frontend/` - 前端文件

## 测试计划

每个模块完成后应该进行测试:

1. **单元测试**: 测试各个类的功能
2. **集成测试**: 测试模块之间的协作
3. **端到端测试**: 完整游戏流程测试
4. **性能测试**: 测试大量Agent时的性能

## 注意事项

1. 先实现基本功能，再优化细节
2. 每个功能都要有清晰的接口
3. 保持代码简洁和可读性
4. 做好错误处理和日志记录
5. 定期进行代码重构
