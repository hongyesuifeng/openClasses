AI Agent 初探实践心得

最近 Agent 的概念到处都是，我想深入学习一下，就搭了这个游戏小镇 demo。写下来分享一下，也方便后续在业务中落地时有个参考。


游戏小镇是什么？

一个模拟游戏开发团队协作的 Multi-Agent 系统。4 个 AI Agent 扮演不同角色，围绕游戏开发任务进行讨论决策。

┌──────────────────────────────────────────────────────────┐
│  游戏小镇 - 《九十九亿大战》开发团队                        │
├──────────────────────────────────────────────────────────┤
│  David (制作人)  │  把控进度、协调资源、最终决策            │
│  Alex (程序员)   │  技术评估、方案实现、性能优化            │
│  Emma (策划)     │  玩法设计、数值平衡、体验把控            │
│  Luna (美术)     │  视觉风格、美术资源、特效表现            │
└──────────────────────────────────────────────────────────┘

主要功能：
- 多角色扮演：每个 Agent 有独立的性格和专业领域
- 实时对话：WebSocket 实现的实时消息推送
- 记忆系统：Agent 能记住之前的讨论内容


Agent 技术原理 vs 游戏小镇实现

1. 角色扮演

Agent 原理                     游戏小镇实现
────────────────────────────────────────────────────────────
System Prompt 定义角色身份  →  AGENT_ROLES 配置文件
包含专业领域和性格特点      →  expertise + personality 字段
约束 Agent 的行为边界       →  场景模板中的角色指引


2. 记忆系统

Agent 原理                     游戏小镇实现
────────────────────────────────────────────────────────────
短期记忆：对话上下文        →  meeting_history 列表
长期记忆：向量检索          →  MemoryManager 类管理
记忆压缩：摘要关键信息      →  _summarize_history() 方法


3. 任务规划与协调

Agent 原理                     游戏小镇实现
────────────────────────────────────────────────────────────
任务分解：拆解复杂任务      →  场景模板定义讨论议程
执行流程：状态机管理        →  MeetingOrchestrator 类
协作模式：多 Agent 配合     →  轮流发言 + 主持人引导


4. Prompt 工程

Agent 原理                     游戏小镇实现
────────────────────────────────────────────────────────────
System Prompt：角色设定    →  _build_system_prompt()
User Prompt：具体任务       →  场景模板 + 当前问题
Few-shot 示例：引导输出     →  templates.py 中的示例


5. 工具使用

Agent 原理                     游戏小镇实现
────────────────────────────────────────────────────────────
工具定义：声明可用能力      →  暂未实现（可扩展）
工具调用：LLM 选择工具      →  未来可接入代码生成、搜索等
结果处理：执行并反馈        →  可用于自动生成文档、代码


一些感悟

Agent 不神秘：公式就是 Agent = LLM + 记忆 + 规划 + (工具)。游戏小镇就是这个公式的具体落地——LLM 提供推理能力，MemoryManager 管理对话历史，Orchestrator 控制会议流程，角色通过 Prompt 工程实现专业化。

业务落地才是难点：Agent 技术本身不难理解，但让它真正解决业务问题，并能支持自主或辅助优化迭代，这件事挺难的，也值得花时间研究。


AI 编程工具对比测试

开发过程中试了几种 AI 编程工具 + 模型组合：

Claude Code + GLM：编码能力强，发散思维也不错。最后版本用的这个。

OpenCode + MiniMax 2.5：开始还行，后面改具体逻辑细节的时候经常写不对，就放弃了。

Gemini：开始效果挺好，UI 布局也比另外几个好看。但几轮交互后感觉变笨了——可能是给我换模型了，手动选的Gemini Pro。

Codex：第一版 UI 交互就放弃了，有点丑。估计是初始文档写得不够完善，输出太保守不够发散。而且codex挺贵的，还是留它干正事吧……
