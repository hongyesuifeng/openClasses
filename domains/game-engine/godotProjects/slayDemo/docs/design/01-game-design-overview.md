# 游戏设计总览

## 一句话概述

一款单人卡牌构筑 Roguelike 游戏：玩家在不断变化的地图中收集卡牌、构筑牌组，通过回合制卡牌战斗击败层层敌人，最终挑战 Act Boss。

---

## 1. 游戏核心概念与定位

### 1.1 游戏类型

- **核心类型**：卡牌构筑（Deckbuilding）+ Roguelike
- **参考标杆**：《杀戮尖塔》（Slay the Spire）
- **运行平台**：桌面端（PC，Windows / Linux / macOS）
- **引擎**：Godot 4.x
- **项目性质**：学习型 Demo，最小可玩原型

### 1.2 核心设计理念

1. **决策密度优先**：每回合的选择都有意义，不存在"无脑最优解"
2. **可读性至上**：玩家能快速理解敌人意图和卡牌效果，决策基于信息而非运气
3. **涌现式策略**：通过卡牌组合与状态交互产生意外而有趣的战术
4. **短反馈循环**：单局 20~40 分钟，每次选择在几秒内看到结果

### 1.3 本 Demo 的范围边界

| 维度 | 首版包含 | 首版不包含 |
|------|---------|-----------|
| 角色 | 1 个（战士） | 多角色、多职业 |
| 卡牌 | 20~30 张 | 75+ 张完整卡池 |
| 敌人 | 6~8 个 | 多 Act 敌人库 |
| 地图 | 1 个 Act | 多章节、分支叙事 |
| 遗物 | 3~5 个（如有余力） | 100+ 遗物系统 |
| 事件 | 2~3 个文本事件 | 完整事件网络 |
| 药水 | 2~3 种基础药水 | 完整药水系统 |
| Meta 进度 | 无 | 解锁系统、成就 |
| 在线功能 | 无 | 排行榜、联机 |

## 2. 目标受众分析

### 2.1 核心受众

- **卡牌游戏爱好者**：熟悉卡牌构筑类游戏的基本概念（费用、抽牌、弃牌堆）
- **Roguelike 玩家**：接受随机性、享受"再来一局"的循环
- **策略游戏玩家**：喜欢通过规划与决策来克服挑战

### 5.2 受众画像

| 属性 | 描述 |
|------|------|
| 年龄 | 18~35 岁 |
| 游戏经验 | 中度到重度，至少接触过一款卡牌或 Roguelike 游戏 |
| 单局时间 | 期望 20~40 分钟一局 |
| 学习曲线 | 能接受 5~10 分钟上手期 |
| 核心驱动力 | 策略规划、卡牌组合的"顿悟时刻"、挑战自我 |

### 2.3 体验目标

- **上手**：5 分钟内理解出牌、能量、格挡的基本规则
- **精通**：通过多局游戏理解卡牌协同、状态叠加、敌人行为预判
- **心流**：每回合 15~30 秒的思考窗口，决策有压力但不焦虑

## 3. 核心体验关键词

| 关键词 | 含义 | 设计体现 |
|--------|------|---------|
| **可读性** | 信息清晰、意图透明 | 敌人意图图标显示、卡牌关键词高亮、伤害预览数字 |
| **决策感** | 每个选择都有代价 | 能量限制、手牌上限、卡牌取舍 |
| **风险与回报** | 高收益伴随高风险 | 精英怪高奖励、自伤卡牌强力 |
| **涌现策略** | 简单规则产生复杂局面 | 状态叠加、多段攻击与力量加成 |
| **节奏感** | 战斗有张有弛 | 前期轻松建立信心、Boss 战紧张刺激 |
| **重玩价值** | 每局体验不同 | 随机地图、随机奖励、不同牌组构建路线 |

## 4. 核心玩法循环

### 4.1 战斗循环（Battle Loop）

```
battle_start
    │
    ▼
player_turn ──── 抽牌（抽牌堆 → 手牌，默认抽 5 张）
    │
    ▼
player_resolve ── 玩家出牌/结束回合
    │               ├── 打牌：检查能量 → 执行效果 → 卡牌进弃牌堆
    │               └── 结束回合：手牌全部进弃牌堆
    ▼
enemy_turn ────── 敌人执行意图
    │               ├── 攻击：对玩家造成伤害
    │               ├── 防御：获得格挡
    │               └── 增益/减益：施加状态
    ▼
回合结束处理
    │               ├── 玩家格挡清零
    │               ├── 状态持续时间递减
    │               └── 检查胜负条件
    ▼
┌─── 胜负判定 ───┐
│               │
│ 玩家 HP <= 0  │──→ battle_lose
│ 敌人全灭      │──→ battle_win
│ 均不满足      │──→ 回到 player_turn
└───────────────┘
```

### 4.2 地图推进循环（Map Progression Loop）

```
选择房间 → 进入房间 → 完成房间事件 → 获得奖励 → 选择下一房间
     │                                           │
     │              ┌────────────────────────────┘
     │              ▼
     │         是否到达 Boss 房间？
     │              │
     │         是 ──┤── 否 → 继续选择房间
     │              │
     │              ▼
     │         Boss 战 → 胜利/失败
     │              │
     └──────────────┘
```

### 4.3 局间循环（Run Loop）

```
开始新局 → 选择初始牌组 → 地图推进 → 局结束（胜利或失败）→ 总结界面 → 开始新局
```

## 5. 系统架构概览

### 5.1 战斗状态机

| 状态 | 说明 |
|------|------|
| `BATTLE_START` | 战斗初始化，洗牌，抽初始手牌 |
| `PLAYER_TURN` | 玩家行动阶段 |
| `PLAYER_RESOLVE` | 单张卡牌效果结算 |
| `ENEMY_TURN` | 敌人行动阶段 |
| `BATTLE_END` | 战斗结束，触发奖励 |

### 5.2 卡组流转

```
抽牌堆（Draw Pile）→ 手牌（Hand）→ 弃牌堆（Discard Pile）→ 洗牌 → 抽牌堆
```

- 手牌上限：10 张
- 每回合抽牌数：5 张
- 抽牌堆为空时：弃牌堆洗牌后成为新的抽牌堆
- 消耗（Exhaust）牌：直接从游戏中移除（本局战斗内）

### 5.3 能量系统

- 基础能量：每回合 3 点
- 回合开始：重置为基础能量值
- 打牌消耗：根据卡牌费用消耗能量
- 能量不足时：无法打出该牌（UI 灰显）

### 5.4 核心数值框架

| 数值 | 初始值 | 说明 |
|------|--------|------|
| 玩家 HP | 80 | 可通过事件/休息点回复 |
| 玩家最大 HP | 80 | 初始上限 |
| 基础能量 | 3 | 每回合恢复 |
| 基础抽牌数 | 5 | 每回合开始 |
| 手牌上限 | 10 | 不可超过 |
| 初始牌组 | 12 张 | 10 张打击 + 5 张防御（注：调整为 10 打击 + 5 防御，实际首版初始 12 张：5 打击 + 4 防御 + 1 重击 + 1 旋风斩 + 1 战嚎）|

> **注**：初始牌组最终数量以卡牌设计文档为准，此处仅为参考框架。

## 6. 美术与音效方向（概述）

### 6.1 美术风格

- 2D 手绘风格或像素风格均可，以实现效率为优先
- 卡牌：清晰的图标 + 简洁的文字说明
- 敌人：辨识度高的剪影或立绘
- UI：深色背景 + 金色/暖色高亮，保持沉浸感

### 6.2 音效需求

- 出牌音效（攻击/技能/能力各一类）
- 伤害音效（轻击/重击）
- 回合切换提示音
- 战斗胜利/失败音乐
- UI 交互音效（点击、悬停、确认）
