## 二、视觉风格现状

### 2.1 UI 整体风格

游戏 UI **全部为程序生成**（`Node.new()` + 主题 override），没有使用 .tscn 预制场景。
- 配色：深色调（背景 #0D0F13 系）+ 金色/琥珀色强调（#F9E066）+ 红色 HP 对比
- 无固定视觉设计语言文档，各场景配色参数散落在代码中

**优点**：程序生成 UI 修改灵活，不依赖 .tscn 文件
**缺点**：视觉一致性依赖开发者的美术直觉，不同场景细节（字体大小、间距、边框圆角）存在微妙差异

### 2.2 卡牌视觉

```
卡牌 art_key 分类（当前卡牌）：
- card_power（5 张 Power 牌）
- card_attack（攻击牌）
- card_skill（技能牌）
```

卡牌图标使用通用模板按类型区分，**没有单独的卡牌插画**。对于 Demo 阶段可接受，但对玩家来说 52 张卡视觉上高度相似，很难快速识别。

### 2.3 敌人视觉

敌人 art_key 与精灵图片映射表（实际状态）：

| art_key | 对应敌人 | 语义匹配度 |
|---------|---------|-----------|
| enemy_slime | 小史莱姆 | ✅ 正确 |
| enemy_mushroom | **尖刺史莱姆、史莱姆王** | ❌ 史莱姆用蘑菇图片 |
| enemy_shadow_mage | 暗影信徒、亡灵法师、诅咒法师 | ⚠️ 三个敌人共用 |
| enemy_bat | 毒素蝙蝠 | ✅ 正确 |
| enemy_skeleton | **盾卫** | ❌ 盾卫用骷髅图片 |
| enemy_gargoyle | 狂战士、石像守卫、狂暴兽人、石像哨兵 | ⚠️ 四个敌人共用 |

- gargoyle 图片被 4 种不同类型敌人共用，无法区分

## 三、视觉缺口清单

### 3.1 立即影响玩家体验

**① 遗物图标覆盖率极低**
- 16 个遗物中，`relic_view_factory` 只硬编码注册了 5 个图标（anchor/lantern/strawberry/meal_ticket/golden_idol）
- 其余 11 个遗物（包括全部 boss 遗物）全部显示纯文字
- assets/ui/relics/ 目录只有这 5 个图标文件

**② 背景复用**
- 主菜单、休息、事件、宝箱、奖励界面共用 bg_map.png + 不同深度蒙层
- 视觉上所有非战斗场景感觉"在同一个地方"
- **建议**：至少为休息点、商店各设计一张独立背景

**③ 敌人 art_key 语义错误**
- 亡灵法师显示蘑菇图片
- **建议**：修正 enemies.json 的 art_key 字段，或补充对应精灵

### 3.2 影响视觉质量

**④ 卡牌无差异化图标**
- 所有攻击牌共用一个图标，所有技能牌共用一个图标
- **建议**：为稀有牌（11 张 rare）优先定制图标，普通牌可继续使用通用模板

**⑤ VFX 粒子效果单薄**
- 特效基于纹理 sprite，没有真正的粒子系统（GPUParticles2D）
- 每次击中只有一个精灵淡出，视觉冲击力有限
- **建议**：至少为 Boss 战增加更丰富的击中特效

**⑥ 状态图标不全**
- frail（虚弱）：icon_path 为空字符串，降级为 emoji "🦴" 显示
- ritual（仪式）、metallicize（金属化）：无图标，显示文字 "★"/"⬡"
- **建议**：补充这 3 个状态的 png 图标

### 3.3 长期改善

**⑦ 卡牌插画**
- 每张卡牌有独立插画是类型游戏的视觉标志
- 短期可用程序生成的几何图形区分
- 长期需要专业插画

**⑧ 字体层级**
- 当前字体规格（font_size 12~38px）分散在代码中，没有统一的排版系统
- 建议定义 4 个层级：标题 32px / 副标题 20px / 正文 16px / 说明 13px

## 五、最终游戏美术愿景

**风格定位**：黑暗奇幻 + 极简 UI，参考《杀戮尖塔》（像素/扁平风）+ 《月圆之夜》（卡牌质感）

**关键视觉里程碑**：
1. **M1（当前）**：程序生成 UI + 基础精灵，保证可玩性
2. **M2（V1.0）**：遗物图标 + 独立场景背景 + 卡牌稀有度区分
3. **M3（V1.5）**：卡牌插画 50%+ + 粒子特效 + 场景动效
4. **M4（正式版）**：全卡牌插画 + 角色立绘 + 过场动画
