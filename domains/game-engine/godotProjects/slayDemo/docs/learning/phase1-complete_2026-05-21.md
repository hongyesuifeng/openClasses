## 二、核心理解总结

### 策划原理层面

1. **核心乐趣 = 组合发现 → 系统掌控感**，不是单卡强度
2. **首版单角色 = 变量控制**，不是偷懒
3. **敌人是牌组能力测试器**，不是血量包
4. **地图选择 = 处境与收益的权衡判断**，不是路线自由
5. **奖励三选一 = 流派方向判断**，不是客观最强单卡选择

### 系统原理层面

1. **三层循环**：战斗（即时决策）+ 地图（局内规划）+ 局间（复盘重试）
2. **战斗是兑现端**：奖励、地图、构筑最后都要在战斗中感受到
3. **状态系统是实现卡牌组合化学反应的核心机制**
4. **伤害计算顺序**：基础伤害 → 力量 → 无力 → 易伤 → 格挡扣除 → HP扣除 → 命中后效果
5. **多敌人战斗的战术深度**：优先目标选择、AOE价值、输出节奏

### 用户信息原理层面

1. **UI支持判断，不替玩家判断**
2. **信息可读性是深度成立的前提**
3. **半引导奖励优于硬引导或完全随机**
4. **动态权重调整要轻量，不保底**

## 三、首版MVP定案

```
角色：1个战士型角色
Act：1个15层Act
流派：抽牌循环流、力量多段流、防御反击流
卡牌：24-30张
敌人：4个普通怪左右、1个精英怪、1个Boss
地图：普通怪、事件、商店、精英、宝箱、休息点、Boss
遗物：5个以内
药水：4个以内
UI：支持玩家判断，不替玩家推荐最优解
```

**实施原则**：
1. 小而闭环优先，不追求内容量
2. 每个系统都必须服务核心链路：流派成立 → 敌人测试 → 地图选择 → 奖励修正 → Boss验证
3. 技术实现优先数据驱动，避免把卡牌和敌人行为写死
4. 美术表现优先可读性，视觉风格服务信息判断
