# Slay the Spire 2 核心设计总结

> 本文档总结游戏的核心策划设计亮点和技术设计亮点。

## 1. 策划设计亮点

### 1.1 卡牌构建 Roguelike 的完美融合

Slay the Spire 2 将卡牌构建（Deckbuilding）与 Roguelike 元素完美融合：

| 设计要素 | 实现方式 |
|---------|---------|
| **风险与回报** | 精英战斗提供强力奖励但需要承担死亡风险 |
| **构建深度** | 每个角色有独特的构建方向（力量流、护甲流、法球流等） |
| **随机性与策略** | 随机奖励 + 玩家选择，既有惊喜又考验策略 |
| **渐进式难度** | 多个 Act 递进，Boss 战作为高潮 |

### 1.2 精心设计的数值系统

#### 动态变量系统

```csharp
// 核心理念：所有数值都是可修改的
protected override IEnumerable<DynamicVar> CanonicalVars => new[]
{
    new DamageVar(6m, ValueProp.Move),  // 基础伤害，可被力量/虚弱修改
    new BlockVar(5m),                    // 基础格挡，可被敏捷修改
};
```

**设计优势**：
- 遗物、能力、事件都可以统一修改数值
- 支持复杂的数值计算链
- 易于扩展新效果

#### 伤害计算链

```
最终伤害 = ((基础伤害 + 力量) × 倍率) - 格挡

其中倍率受：
- 虚弱(Weak)：×0.75
- 易伤(Vulnerable)：×1.5
```

### 1.3 角色差异化设计

每个角色都有独特的核心机制：

| 角色 | 核心机制 | 设计理念 |
|------|---------|---------|
| **Ironclad** | 力量叠加、消耗配合 | 简单直接，适合新手 |
| **Silent** | 毒药、匕首、无限连 | 精密计算，适合高玩 |
| **Defect** | 法球系统、能力叠加 | 策略规划，适合策略玩家 |
| **Regent** | 星星资源、神圣主题 | 资源管理，新颖体验 |

### 1.4 地图生成与节奏控制

#### 节点分布规则

```
设计目标：保证游戏节奏

限制规则：
- 上方3行不能有休息点（避免过早恢复）
- 父子节点不能是同类型特殊节点
- 同一层只能有1个休息点/商店

效果：
- 玩家需要权衡风险和路线
- 每局游戏都有不同的策略选择
```

### 1.5 遗物触发系统

```csharp
// 设计理念：事件驱动，解耦合
public abstract class RelicModel
{
    // 遗物只需要重写关心的方法
    public virtual Task AfterCombatVictory(CombatRoom room) => Task.CompletedTask;
    public virtual decimal ModifyDamageAdditive(...) => 0;
}
```

**设计优势**：
- 新遗物不需要修改现有代码
- 遗物效果可以自由组合
- 支持模组扩展

### 1.6 意图系统（Intent System）

```
玩家可以看到敌人的下一个行动：
- 攻击意图：显示伤害数值
- 防御意图：显示即将获得格挡
- 增益/减益意图：显示将应用的Buff/Debuff

设计效果：
- 增加策略深度：玩家可以提前规划
- 减少随机抱怨：玩家知道接下来会发生什么
- 增强学习感：玩家可以理解AI行为模式
```

## 2. 技术设计亮点

### 2.1 架构设计

#### 分层架构

```
Game Layer        - 游戏逻辑（CombatManager, RunState）
Model Layer       - 数据模型（CardModel, RelicModel）
Content Layer     - 内容定义（卡牌、遗物、角色）
Infrastructure    - 基础设施（Hook, Mod, Network）
```

#### 设计原则

- **单一职责**：每个类只做一件事
- **开闭原则**：通过继承和Hook扩展，不修改现有代码
- **依赖倒置**：高层模块依赖抽象接口

### 2.2 Hook 钩子系统

```csharp
// 设计理念：一切皆可修改
public static class Hook
{
    // 几乎每个关键行为都有对应的 Hook
    public static decimal ModifyDamage(...);
    public static decimal ModifyBlockGained(...);
    public static int ModifyHandDraw(...);
    // ... 数百个 Hook 点
}
```

**技术优势**：
- 遗物、能力、模组都可以通过 Hook 修改游戏行为
- 核心代码保持简洁
- 支持复杂的交互效果

### 2.3 异步战斗系统

```csharp
// 支持多人同步的异步架构
public async Task ExecuteEnemyTurn()
{
    foreach (var enemy in enemies)
    {
        await enemy.PerformMove();  // 异步执行，可被同步
    }
}
```

**技术优势**：
- 支持多人游戏同步
- 非阻塞执行，UI 流畅
- 支持撤销和重放

### 2.4 数据驱动设计

#### 内容定义

```csharp
// 所有游戏内容都是数据
public sealed class Strike : CardModel
{
    protected override IEnumerable<DynamicVar> CanonicalVars =>
        new[] { new DamageVar(6m, ValueProp.Move) };
}
```

**技术优势**：
- 添加新内容只需创建新类
- 支持热加载和模组
- 易于测试和平衡

### 2.5 存档系统设计

```
分层保存：
- SettingsSave：设置（独立于运行）
- ProgressSave：进度（解锁、统计）
- RunSave：运行（当前游戏状态）
- RunHistorySave：历史（记录）

技术特点：
- Schema 版本控制，支持迁移
- Steam 云同步集成
- 异步保存，不阻塞游戏
```

### 2.6 模组系统架构

```
Hook 订阅 → 懒加载执行 → 内容注入

技术特点：
- Harmony Patch 支持运行时修改
- 依赖拓扑排序加载
- Steam 创意工坊集成
- 模组池冻结机制
```

### 2.7 网络同步设计

```
核心原则：确定性同步

实现方式：
- RNG 状态同步：所有客户端使用相同随机序列
- 行动队列同步：确保行动按相同顺序执行
- 玩家数据同步：定期同步完整状态

技术特点：
- 位级序列化节省带宽
- Steam P2P 传输
- 断线重连支持
```

## 3. 可借鉴的设计模式

### 3.1 动态变量模式

**适用场景**：需要灵活修改数值的系统

```
设计要点：
1. 所有数值使用变量对象而非原始类型
2. 支持加法和乘法修改链
3. 清晰的修改优先级
```

### 3.2 Hook 钩子模式

**适用场景**：需要高度可扩展的系统

```
设计要点：
1. 在关键行为处预留 Hook 点
2. Hook 返回值可修改行为结果
3. 支持多个订阅者
```

### 3.3 命令模式

**适用场景**：需要撤销、重放、同步的操作

```csharp
// 所有操作封装为命令
await DamageCmd.Attack(6).Targeting(enemy).Execute();
await CardCmd.DrawCards(2);
await PowerCmd.ApplyPower<StrengthPower>(3);
```

### 3.4 状态机模式

**适用场景**：复杂的状态转换

```
应用实例：
- 怪物 AI：MonsterMoveStateMachine
- 战斗流程：CombatPhase 枚举
- UI 状态：各种屏幕状态
```

## 4. 技术栈选择分析

### 4.1 Godot 4.5 + C#

**选择理由**：

| 方面 | 优势 |
|------|------|
| **开发效率** | C# 强类型、IDE 支持好 |
| **性能** | C# 比 GDScript 快，适合复杂逻辑 |
| **跨平台** | Godot 原生支持多平台 |
| **开源** | 无授权费用，社区活跃 |
| **模组支持** | C# Assembly 动态加载方便 |

### 4.2 FMOD 音频系统

**选择理由**：
- 专业级音频中间件
- 支持复杂的音频交互
- 跨平台一致性

### 4.3 Harmony 补丁框架

**选择理由**：
- 运行时修改方法
- 无需修改源码
- 模组友好

## 5. 总结

`★ Insight ─────────────────────────────────────`
**Slay the Spire 2 的成功秘诀：**

**策划层面**：
1. 卡牌构建 + Roguelike 的完美融合
2. 深度数值系统，简单规则产生复杂策略
3. 角色差异化，每个角色都是新体验
4. 意图系统增加策略深度和可学习性

**技术层面**：
1. 高度模块化的架构设计
2. Hook 钩子系统实现极致可扩展性
3. 数据驱动设计，内容与代码分离
4. 完善的多人同步和模组支持

**核心理念**：简单的规则 + 深度的交互 = 无限的重玩价值
