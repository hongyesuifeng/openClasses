# Slay the Spire 2 项目概述

> 本文档基于游戏源代码进行逆向分析，仅供学习研究使用。

## 1. 项目基本信息

### 1.1 游戏简介

**Slay the Spire 2（杀戮尖塔2）** 是由 MegaCrit 开发的策略卡牌Roguelike游戏，是经典游戏《杀戮尖塔》的正统续作。游戏融合了卡牌构建与Roguelike元素，玩家通过构建独特的牌组、收集遗物、挑战各色敌人来攀登尖塔。

### 1.2 技术栈

| 类别 | 技术选型 |
|------|----------|
| **游戏引擎** | Godot 4.5 |
| **开发语言** | C# 9.0 (.NET 9.0) |
| **音频系统** | FMOD |
| **动画系统** | Spine |
| **错误监控** | Sentry |
| **发行平台** | Steam (Steamworks.NET) |
| **模组框架** | 0Harmony, MonoMod |

### 1.3 核心依赖

```
├── Steamworks.NET        - Steam SDK 集成
├── 0Harmony              - 运行时方法修补框架
├── Sentry                - 错误监控和报告
├── FMOD GDExtension      - 专业音频中间件
├── MonoMod               - 代码修改框架
├── SmartFormat           - 字符串格式化
└── System.Text.Json      - JSON 序列化
```

### 4.2 核心系统模块

| 模块 | 职责 | 核心类 |
|------|------|--------|
| **卡牌系统** | 管理卡牌定义、效果、升级 | CardModel, CardPool, DynamicVar |
| **战斗系统** | 控制战斗流程、伤害计算 | CombatManager, CombatState, AttackCommand |
| **角色系统** | 管理可玩角色、属性 | CharacterModel, PlayerCombatState |
| **遗物系统** | 管理遗物效果、触发 | RelicModel, RelicPool |
| **地图系统** | 生成地图、节点管理 | ActMap, MapPoint, MapPointType |
| **事件系统** | 处理事件选择、结果 | EventModel, EventOption |
| **存档系统** | 数据持久化、云同步 | SaveManager, RunState, ProgressState |
| **模组系统** | 支持MOD加载、扩展 | ModManager, Hook, ModHelper |
| **多人系统** | 网络同步、联机对战 | NetGameService, CombatStateSynchronizer |

## 5. 设计特点

### 5.1 架构特点

1. **高度模块化**：每个系统独立封装，通过接口通信
2. **数据驱动**：卡牌、遗物、事件等内容全部数据化定义
3. **事件驱动**：通过 Hook 系统实现松耦合扩展
4. **状态机模式**：战斗、AI、UI 均采用状态机管理

### 5.2 技术亮点

- **动态变量系统**：卡牌效果数值支持动态计算和修改
- **Hook 钩子系统**：几乎任何游戏行为都可被模组修改
- **多层存档架构**：分离设置、进度、运行时数据
- **异步战斗系统**：支持多人同步的非阻塞战斗处理
- **创意工坊集成**：完整的 Steam 模组生态系统

### 5.3 可扩展性

```
Modding Capabilities
├── 添加新卡牌
├── 添加新角色
├── 添加新遗物
├── 添加新事件
├── 修改游戏逻辑
├── 自定义UI
└── 完全新的游戏模式
```
