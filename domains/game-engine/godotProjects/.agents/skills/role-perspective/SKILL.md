# 角色视角切换技能

此技能帮助用户从不同游戏开发角色的专业视角分析问题，实现跨角色学习。

---

## 使用场景

- 用户想了解某个问题从不同角色视角的看法
- 用户在进行跨角色协作时需要理解其他视角
- 用户想发现自己的视角盲区

---

## 可用角色

| 角色 | 命令 | 专业视角 |
|------|------|---------|
| 游戏制作人 | `producer` | 项目进度、范围控制、风险管理 |
| 游戏开发者 | `developer` | 技术架构、代码实现、性能优化 |
| 游戏美术 | `artist` | 视觉风格、资源管理、UI设计 |
| 游戏策划 | `designer` | 玩法机制、数值平衡、玩家体验 |

---

## 角色定义位置

所有角色定义存放在：
```
.agents/roles/
├── producer/ROLE.md
├── developer/ROLE.md
├── artist/ROLE.md
└── designer/ROLE.md
```

---

## 输出模板

当切换到某个角色视角时，按以下结构输出：

```markdown
## {角色名}视角: {问题}

### 我看到了什么
- 从这个角色视角观察到的事物
- 这个角色会注意到的细节

### 我关心什么
- 这个角色视角的优先级
- 这个角色的关注点和担忧

### 我会怎么做
- 这个角色视角的建议行动
- 这个角色会做出的决策

### 为什么（我的视角）
- 这个角色视角的理由和依据
- 这个角色的思维方式

### 其他角色可能怎么看
- 制作人: {...}
- 开发者: {...}
- 美术: {...}
- 策划: {...}
```

---

## 执行步骤

1. **读取角色定义** - 从 `.agents/roles/{role}/ROLE.md` 读取角色定义

2. **理解角色视角** - 分析该角色的：
   - 核心职责
   - 能力边界
   - 关注点
   - 工作模式

3. **应用视角分析** - 用该角色的思维方式分析用户的问题

4. **输出结构化结果** - 按模板输出分析结果

5. **对比其他视角** - 简要说明其他角色可能的看法

## 示例

### 用户输入
```
/role-switch designer
问题：卡牌 UI 显示功能
```

### 输出
```markdown
## 策划视角: 卡牌 UI 显示

### 我看到了什么
- 卡牌需要显示：名称、费用、描述、类型、稀有度
- 玩家需要在战斗中快速判断是否打出这张牌

### 我关心什么
- 信息层级是否清晰？玩家能一眼看到费用吗？
- 关键词高亮了吗？「护甲」「中毒」是否容易识别？
- 卡牌描述是否简洁？会不会太长截断？
- 玩家能看到卡牌的实际效果数值吗？

### 我会怎么做
- 设计卡牌模板，明确信息优先级：费用 > 名称 > 描述 > 其他
- 定义关键词颜色规范：增益用绿色，减益用红色
- 与美术讨论卡牌尺寸和布局
- 与开发讨论动态文本解析（如"造成 {damage} 点伤害"）

### 为什么（我的视角）
- 作为策划，我关心玩家能否快速做出有意义的决策
- 信息不清晰会导致玩家决策困难，影响游戏体验

### 其他角色可能怎么看
- **制作人**: 关注这是否影响里程碑，需要多少开发时间
- **开发者**: 关注数据结构如何映射到 UI，性能开销如何
- **美术**: 关注视觉风格、配色、字体可读性
```
