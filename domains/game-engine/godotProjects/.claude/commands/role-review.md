# 跨角色评审

请求其他角色从其专业视角评审你的工作，获取跨角色反馈。

## 用法

```
/role-review <目标角色> <评审内容>
```

**目标角色**:
- `producer` - 游戏制作人
- `developer` - 游戏开发者
- `artist` - 游戏美术
- `designer` - 游戏策划

## 示例

```
/role-review designer docs/tech/03-card-effect-system.md
/role-review artist docs/design/02-card-design.md
/role-review developer docs/design/07-combat-encounter-design.md
/role-review producer 当前 M1 里程碑进度
```

## 执行步骤

1. 读取目标角色定义 `.agents/roles/{role}/ROLE.md`
2. 从目标角色视角审视评审内容
3. 提供该角色视角的专业反馈
4. 更新 `collaboration-context.md` 的评审队列

## 评审输出格式

```markdown
## {角色}评审反馈

### 评审内容
{被评审的内容摘要}

### 从{角色}视角看

#### 做得好的地方
- ...

#### 需要改进的地方
- ...

#### 建议和问题
- ...

### 与{角色}相关的影响
- 这个设计对{角色}工作的影响
- 需要调整的地方

### 后续行动
- [ ] 行动项 1
- [ ] 行动项 2
```

## 评审示例

### 开发者评审设计文档

```markdown
## 开发者评审: 卡牌设计文档

### 评审内容
docs/design/02-card-design.md

### 从开发者视角看

#### 做得好的地方
- 卡牌效果描述清晰，容易映射到代码逻辑
- 数值参数明确，便于配置

#### 需要改进的地方
- 部分效果描述不够精确，如"中等伤害"需要量化
- 未说明卡牌效果的优先级顺序

#### 建议和问题
- 建议添加效果类型分类（即时/持续/触发）
- 需要明确状态叠加规则（叠加还是刷新？）

### 与开发相关的影响
- 需要设计通用的效果执行框架
- 数据结构需要支持效果参数化

### 后续行动
- [ ] 策划补充效果类型定义
- [ ] 开发者设计效果系统架构
```

## 协作上下文更新

评审完成后，更新 `.agents/shared/collaboration-context.md`：

```markdown
### 评审队列

| 提交者 | 内容 | 评审角色 | 状态 | 时间 |
|-------|------|---------|------|------|
| {用户} | {内容} | {角色} | 已完成 | {时间} |
```
