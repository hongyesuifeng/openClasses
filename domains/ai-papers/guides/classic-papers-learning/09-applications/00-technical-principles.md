# 技术原理：知识增强与应用

> 从"知道"到"做到"

## 核心概念

### 1. 检索增强生成（RAG）

核心问题：LLM 的知识是静态的（训练数据截止日期），且可能产生幻觉。

RAG 的解决方案：在生成前先检索相关知识。

```
用户提问
    ↓
检索器（Retriever）: 从知识库中找到相关文档
    ↓
拼接：问题 + 检索到的文档
    ↓
生成器（Generator）: 基于检索到的内容生成回答
```

优势：
- 知识可更新（只需更新知识库）
- 减少幻觉（基于真实文档）
- 可追溯（引用来源）

### 2. 大规模弱监督（Large-Scale Weak Supervision）

Whisper 的核心创新：不追求标注质量，追求数据规模。

```
传统方法: 1万小时人工标注 → 高质量但有限
Whisper: 68万小时机器伪标注 → 有噪声但海量
```

关键洞察：数据规模可以弥补标注质量的不足。

### 3. 推理+行动（Reasoning + Acting）

ReAct 的核心框架：

```
循环：
1. 思考（Thought）: 分析当前情况，决定下一步
2. 行动（Action）: 执行工具调用（搜索、计算等）
3. 观察（Observation）: 获取工具返回结果
4. 重复直到得出最终答案
```

vs 纯 CoT：
- CoT: 只有思考，无法获取外部信息
- ReAct: 思考+行动，可以实时查询和验证

### 4. 自监督工具学习（Self-Supervised Tool Learning）

Toolformer 的核心方法：

```
1. 给 LLM 展示 API 调用的示例
2. 让 LLM 自己决定在哪些位置插入 API 调用
3. 执行 API 调用，获取结果
4. 过滤：只保留真正有帮助的调用
5. 用这些数据微调 LLM
```

模型学会了：何时需要工具、调用哪个工具、如何使用返回结果。

## 应用架构对比

| 方法 | 核心能力 | 局限性 |
|------|---------|--------|
| RAG | 知识检索 | 检索质量决定上限 |
| ReAct | 推理+行动 | 需要工具生态 |
| Toolformer | 自动工具使用 | 工具种类有限 |
| Whisper | 语音理解 | 仅限音频模态 |
