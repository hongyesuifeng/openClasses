# ReAct（2023）— 推理与行动的协同：AI Agent 的核心框架

## 基本信息
- **论文**: ReAct: Synergizing Reasoning and Acting in Language Models
- **作者**: Yao et al., Princeton University
- **机构**: Princeton University
- **年份**: 2023
- **状态**: 未阅读

## 解决了什么问题

Chain-of-Thought（CoT）让大模型学会了"推理"——在给出答案前先思考推理步骤。但 CoT 有一个根本局限：**推理过程完全是"内部思考"，模型无法与外部世界交互。**

例如，如果你问模型"2024 年诺贝尔物理学奖得主是谁"，CoT 可以让模型写出推理步骤，但如果模型的训练数据中不包含这个信息，它就无法给出正确答案——无论推理多少步都没用。

类似地，如果问"北京现在的天气怎么样"，纯推理无法获取实时信息。

更一般的问题是：**AI 系统如何同时具备"推理能力"（思考问题、制定计划）和"行动能力"（执行操作、获取信息、调用工具）？**

ReAct 试图解决这个问题：让大模型在推理过程中可以执行行动（如搜索、查询数据库），并根据行动结果继续推理。

## 核心方法

ReAct 的核心框架是一个 **Thought → Action → Observation 循环**：

### 1. Thought（思考）

模型分析当前情况，决定下一步做什么：
- "我需要知道 2024 年诺贝尔物理学奖的信息"
- "我应该搜索一下"
- "搜索结果说得主是 John Hopfield 和 Geoffrey Hinton"

Thought 本质上是模型的"内心独白"，用于组织推理和规划行动。

### 2. Action（行动）

模型执行具体的操作：
- **Search[query]**：搜索引擎查询
- **Lookup[keyword]**：在当前文档中查找关键词
- **Finish[answer]**：给出最终答案
- 可以扩展为任何工具调用（API、数据库查询、代码执行等）

### 3. Observation（观察）

系统返回行动的结果：
- Search 返回搜索结果摘要
- Lookup 返回文档中匹配的段落
- API 返回调用结果

### 完整的 ReAct 循环示例

```
问题：2024 年诺贝尔物理学奖得主是谁？

Thought 1：我需要搜索 2024 年诺贝尔物理学奖的信息。
Action 1：Search[2024 Nobel Prize in Physics]
Observation 1：2024 年诺贝尔物理学奖授予 John Hopfield 和 Geoffrey Hinton，
              "表彰他们在人工神经网络机器学习方面的基础性发现和发明"。

Thought 2：我找到了答案。得主是 John Hopfield 和 Geoffrey Hinton。
Action 2：Finish[John Hopfield 和 Geoffrey Hinton]
```

### 与 CoT 的关键区别

| 维度 | Chain-of-Thought | ReAct |
|------|------------------|-------|
| 信息来源 | 仅模型内部知识 | 模型知识 + 外部信息 |
| 能力 | 推理 | 推理 + 行动 |
| 可验证性 | 推理链可审查 | 推理链 + 行动记录可审查 |
| 实时信息 | 不支持 | 支持（通过搜索等工具） |
| 错误纠正 | 不支持 | 可以通过新的观察修正推理 |

ReAct 本质上是 CoT 的"行动增强版"——在推理过程中增加了与外部世界交互的能力。

### 为什么 Thought-Action-Observation 循环有效？

1. **信息补充**：模型可以通过行动获取自己不知道的信息
2. **推理校准**：外部观察可以作为"事实锚点"，防止推理偏离事实
3. **可追溯性**：每一步推理和行动都有明确记录，方便审计和调试
4. **灵活性**：模型可以根据观察结果动态调整策略

## 关键实验结果

- **HotPotQA**（多跳问答）：ReAct 显著超越纯推理方法（CoT）和纯行动方法（Act-only）
- **FEVER**（事实验证）：在需要多步推理和信息检索的验证任务上表现优异
- **ALFWorld**（文本游戏）：在需要多步操作的虚拟环境中，ReAct 的成功率远高于纯推理
- **关键对比**：
  - CoT-only（只推理不行动）：在需要外部信息的任务上经常出错
  - Act-only（只行动不推理）：行动效率低，经常执行无关操作
  - **ReAct（推理+行动协同）**：在准确率和效率上都是最优的

## 为什么重要

ReAct 的重要性远超其实验结果本身：

1. **AI Agent 的核心框架**：ReAct 的 Thought-Action-Observation 循环成为后来几乎所有 AI Agent 系统的基础架构。LangChain、AutoGPT、MetaGPT 等 Agent 框架都直接采用了这个设计模式。

2. **推理与行动的协同效应**：ReAct 证明了"推理"和"行动"不是两个独立的能力，而是可以互相增强的：
   - 推理指导行动（"我应该搜索什么"）
   - 行动校准推理（"搜索结果告诉我什么"）

3. **LLM 从"聊天机器人"到"智能体"的进化**：ReAct 之前，LLM 的主要角色是"回答问题"。ReAct 之后，LLM 可以"执行任务"——这标志着从"被动工具"到"主动智能体"的转变。

4. **可审计的 AI 决策**：ReAct 的每一步推理和行动都有明确记录，使 AI 的决策过程完全可追溯。在安全关键场景中，这一点极其重要。

## 后续影响

- **LangChain / LlamaIndex**：采用 ReAct 模式作为 Agent 的核心执行循环
- **AutoGPT / BabyAGI**：自主 AI Agent 的早期尝试，基于 ReAct 模式
- **GPT-4 + Tools**：OpenAI 的 Function Calling 和 GPT-4 的工具使用能力
- **Claude Tool Use**：Anthropic 的工具使用能力
- **企业 AI Agent**：客户服务、数据分析、自动化工作流等领域的 AI Agent
- **游戏 AI**：游戏中的 AI NPC 可以通过 ReAct 框架与游戏世界交互

## 个人理解

ReAct 的核心洞察——"推理和行动应该交替进行"——看似简单，实际上解决了 AI 系统设计中的一个根本问题。

传统的 AI 系统要么是"纯推理型"（如专家系统），要么是"纯反应型"（如行为主义机器人）。前者擅长思考但无法行动，后者擅长行动但缺乏深度推理。ReAct 告诉我们：**最优的方案不是二选一，而是让推理和行动交替进行、互相增强。**

这与人类的认知过程高度一致：当面对复杂问题时，我们不会只在脑子里想（纯推理），也不会盲目行动（纯反应），而是"想一想 → 做一做 → 看看结果 → 再想一想"。ReAct 让 AI 也能这样做。

从游戏开发的角度看，ReAct 对 AI NPC 的设计有直接的启发。传统的 NPC 行为树是"纯反应"式的——看到玩家就攻击、血量低就逃跑。而基于 ReAct 的 NPC 可以"思考"当前情境、"查询"游戏世界信息、"决定"最佳行动，然后"观察"行动结果并调整策略。这会让 NPC 的行为更加智能和可信。
