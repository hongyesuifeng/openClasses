# Toolformer（2023）— 语言模型自学使用工具：自监督工具学习

## 基本信息
- **论文**: Toolformer: Language Models Can Teach Themselves to Use Tools
- **作者**: Schick et al., Meta (Facebook)
- **机构**: Meta AI Research (FAIR)
- **年份**: 2023
- **状态**: 未阅读

## 解决了什么问题

大语言模型虽然能力强大，但有几个根本性弱点：

1. **数学计算不准**：大模型做复杂计算经常出错（如 3742 x 8391），因为它不是"计算器"——它是通过模式匹配来"猜测"答案的
2. **事实性信息可能过时或错误**：模型的内部知识可能在训练时就已过时
3. **无法执行实际操作**：不能发邮件、不能查日历、不能调用 API

人类在遇到这些问题时会使用工具——用计算器做数学、用搜索引擎查信息、用日历安排日程。问题是：**能否让大模型也学会在合适的时机使用合适的工具？**

此前的方案（如 ReAct）需要手工设计工具调用规则和 prompt 模板，每个工具都需要专门适配。Toolformer 试图回答一个更深层的问题：**能否让语言模型自己学会什么时候、在什么位置调用什么工具——完全通过自监督学习，不需要人工标注？**

## 核心方法

Toolformer 的核心是**自监督工具学习（Self-Supervised Tool Learning）**——让模型自己"教"自己使用工具。

### 完整训练流程

#### 步骤 1：LLM 生成 API 调用位置

给定一段文本，让语言模型在文本中插入"工具调用标记"：

```
原文："2020年的人口约为 [Search(2020年世界人口)] → 约78亿"
```

模型被提示在合适的位置插入 API 调用（如 `[Calculator(3742 * 8391)]`、`[Search(query)]`）。

#### 步骤 2：执行 API 调用

实际执行模型建议的 API 调用，获取返回结果：

```
[Calculator(3742 * 8391)] → 31,412,622
[Search(2020年世界人口)] → 约 78 亿人
```

#### 步骤 3：过滤有用的调用

关键步骤——不是所有 API 调用都是有用的。Toolformer 用一个过滤标准来评估：

- 对比两种情况下的文本困惑度（perplexity）：
  - **有 API 结果**："2020年的人口约为 78 亿"（包含工具返回值）
  - **无 API 结果**："2020年的人口约为 ___"（没有工具返回值）
- 如果"有 API 结果"的困惑度显著更低，说明这个工具调用是有用的，保留
- 否则丢弃（说明模型不需要这个工具调用也能正确预测文本）

#### 步骤 4：微调

用过滤后的"文本 + 工具调用 + 结果"数据微调语言模型，让它学会：
- 在什么位置插入工具调用
- 调用什么工具
- 传什么参数
- 如何在文本中整合工具返回的结果

### 支持的工具

Toolformer 论文中演示了五种工具：

1. **计算器（Calculator）**：精确的数学计算
   - 解决"3742 x 8391 = ?"类的精确计算问题
   - 在数学相关任务上准确率大幅提升

2. **问答系统（QA）**：基于事实的问答
   - 回答需要外部知识的问题
   - 可以接入知识图谱或搜索引擎

3. **搜索引擎（Search）**：网络搜索
   - 获取实时信息、查找特定内容
   - 解决知识过时问题

4. **日历（Calendar）**：日期和时间查询
   - 获取当前日期、计算时间差
   - 解决"今天是几号"类的问题

5. **机器翻译（Translator）**：多语言翻译
   - 在需要翻译的上下文中自动调用

## 关键实验结果

- **数学推理（GSM8K）**：使用计算器工具后，准确率显著提升
- **事实性问答**：使用搜索工具后，在需要最新信息的问题上表现大幅改善
- **时间相关推理**：使用日历工具后，在需要日期计算的任务上准确率接近 100%
- **多语言任务**：使用翻译工具后，跨语言任务的流畅度和准确性提升
- **关键发现**：模型学会了"何时使用工具"——不是在所有地方都调用工具，而是在模型自身能力不足时才调用

### 过滤的重要性

消融实验表明，过滤步骤至关重要：
- 不过滤（保留所有 API 调用）：模型学会了在不需要的地方也调用工具，性能下降
- 过滤（只保留有用的调用）：模型精确地学会了"何时需要工具"

## 为什么重要

Toolformer 是 LLM 工具使用能力的里程碑，其重要性体现在：

1. **自监督学习范式的创新**：Toolformer 不需要人工标注"这里应该调用什么工具"。模型通过自监督方式学会了何时、何地、如何使用工具。这大大降低了工具集成的人力成本。

2. **为 Function Calling 铺路**：Toolformer 的思想直接影响了后来 OpenAI 的 Function Calling 功能和 Anthropic 的 Tool Use 功能。现代 LLM 的工具调用能力都可以追溯到 Toolformer 的开创性工作。

3. **LLM 能力边界的扩展**：通过工具使用，LLM 突破了自身的根本限制——不能精确计算就用计算器，不知道事实就搜索，不知道日期就查日历。每个工具都扩展了模型的能力边界。

4. **"有用性过滤"的设计思想**：Toolformer 的过滤机制——"只有当工具调用确实降低了困惑度时才保留"——是一个优雅的设计。它让模型学会了"克制"：不是盲目使用工具，而是在真正需要时才使用。

## 后续影响

- **OpenAI Function Calling**：GPT-4/GPT-4o 的函数调用功能
- **Anthropic Tool Use**：Claude 的工具使用能力
- **LangChain Tools**：LangChain 框架中的工具集成系统
- **Gorilla**：专门训练 LLM 调用 API 的模型
- **AI Agent 生态**：Toolformer 的思想成为 AI Agent 的基础设施——Agent 需要调用各种工具来完成复杂任务
- **AutoGPT / CrewAI / MetaGPT**：自主 Agent 系统中的工具调用机制

## 个人理解

Toolformer 最精妙的设计是"过滤"这一步。它解决了一个微妙但关键的问题：**如何让模型学会"不滥用"工具？**

如果没有过滤，模型可能会在每个位置都调用计算器，即使面对简单的"1+1"也会调用。这不仅浪费计算资源，还会降低生成质量（因为工具调用打断了正常的文本生成流程）。过滤机制通过"困惑度对比"自动判断哪些调用是真正有用的——这相当于教模型"在需要帮助时才求助"。

从更广阔的视角看，Toolformer 代表了 AI 发展的一个重要方向：**AI 不需要自己会做所有事情，而是需要知道什么时候应该求助外部工具。** 这与人类专家的工作方式高度一致——数学家不需要心算大数乘法，只需要知道什么时候该用计算器。

这对游戏 AI 的启示是：**游戏中的 AI 角色不需要完全靠自己做决策，而是可以"使用工具"——查询游戏数据库、调用游戏 API、与其他角色交互。** 这种"工具使用"的范式比"让模型学会所有能力"更灵活、更可扩展。

Toolformer 与 ReAct 的区别也值得注意：ReAct 是在推理时通过 prompt 引导模型使用工具，Toolformer 是通过训练让模型"内化"工具使用能力。两种方法可以结合使用——训练时学会工具使用的基本模式，推理时通过 ReAct 框架动态选择工具。
