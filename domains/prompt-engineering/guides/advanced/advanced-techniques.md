## 1. 思维链 (Chain-of-Thought, CoT)

### 1.1 核心原理

思维链是一种提示技术，通过引导模型"一步步思考"，将复杂推理任务分解为多个简单的推理步骤。

**为什么有效？**
- 降低每一步推理的复杂度
- 减少中间步骤的错误
- 提供可追溯的推理过程
- 适合数学、逻辑、代码推理等任务

### 1.2 基础思维链

**触发短语**：
- "让我们一步步思考"
- "请逐步分析"
- "按以下步骤推理"

**示例：数学问题**

```
问题：一个篮球和一个球拍总共 110 美元，球拍比篮球贵 100 美元。篮球多少钱？

请一步步思考并给出答案。
```

**预期输出**：
```
让我们一步步分析：
1. 设篮球的价格为 x 美元
2. 球拍的价格是 x + 100 美元
3. 总价方程：x + (x + 100) = 110
4. 化简：2x + 100 = 110
5. 解方程：2x = 10，x = 5
答案：篮球的价格是 5 美元
```

### 1.3 结构化思维链

**模板**：
```
# 问题分析
{问题描述}

# 解决步骤
步骤1：{第一步}
步骤2：{第二步}
步骤3：{第三步}

# 最终答案
{结论}
```

### 1.4 代码推理示例

```
请分析以下代码的时间复杂度，并逐步说明你的推理过程：

public void FindDuplicates(int[] arr) {
    for (int i = 0; i < arr.Length; i++) {
        for (int j = i + 1; j < arr.Length; j++) {
            if (arr[i] == arr[j]) {
                Console.WriteLine($"Duplicate found: {arr[i]}");
            }
        }
    }
}

请按以下步骤分析：
1. 识别代码中的循环结构
2. 分析每个循环的执行次数
3. 计算总操作次数
4. 得出时间复杂度结论
```

## 2. 自我一致性 (Self-Consistency)

### 2.1 核心原理

让模型对同一问题进行多次推理，然后通过投票选择最常见/最一致的答案。

**适用场景**：
- 数学推理问题
- 逻辑推理任务
- 需要高准确性的场景

### 2.2 实现方法

**方法1：多次推理**
```
请对以下问题进行5次独立的推理分析，每次都"从头思考"，
然后给出最一致的答案。

问题：{问题}
```

**方法2：不同角度**
```
从以下3个角度分析这个问题，然后综合给出最可靠的答案：
1. 数学角度
2. 实际应用角度  
3. 边界情况角度

问题：{问题}
```

## 3. 检索增强生成 (RAG) 提示设计

### 3.1 RAG 基础流程

```
用户问题 → 检索相关文档 → 构建增强提示 → 生成答案
```

### 3.2 RAG 提示词模板

**基础模板**：
```markdown
# 参考文档
{检索到的相关文档内容}

# 用户问题
{用户原始问题}

# 要求
- 基于以上参考文档回答问题
- 如果文档中没有相关信息，明确说明
- 引用文档中的具体内容支持你的答案
```

**优化模板**：
```markdown
# 任务
你是一个专业的问题回答助手。请基于提供的参考文档回答用户问题。

# 参考文档
文档1：
{文档1内容}

文档2：
{文档2内容}

# 用户问题
{用户问题}

# 回答要求
1. 仅基于参考文档回答，不要使用外部知识
2. 明确指出答案来自哪个文档的哪部分
3. 如果文档信息不足，明确说明
4. 以结构化的方式组织答案

# 输出格式
## 答案
{主要答案}

## 依据
- 文档1：{引用内容}
- 文档2：{引用内容}

## 补充说明
{如果需要}
```

### 3.3 RAG 最佳实践

1. **文档质量**：确保检索到的文档相关且准确
2. **信息排序**：将最相关的文档放在前面
3. **明确引用**：要求模型明确引用信息来源
4. **处理冲突**：当文档信息冲突时，要求模型说明

## 4. 工具调用提示设计

### 4.1 ReAct 模式

ReAct = Reasoning（推理）+ Acting（行动）

**循环结构**：
```
思考(Thought) → 行动(Action) → 观察(Observation) → 重复
```

### 4.2 工具调用提示模板

```markdown
# 可用工具
你拥有以下工具可以调用：

1. search_database(query): 搜索数据库
   - 参数：query (string) - 搜索关键词
   - 返回：匹配的记录列表

2. calculate(expression): 计算数学表达式
   - 参数：expression (string) - 数学表达式
   - 返回：计算结果

# 工作流程
对于每个问题：
1. 思考：分析需要什么信息
2. 行动：选择合适的工具并准备参数
3. 观察：查看工具返回结果
4. 重复：基于结果继续或给出答案

# 格式要求
思考：{你的思考过程}
行动：{工具名}({参数})
观察：{工具返回结果}
（循环直到得到答案）

最终答案：{最终答案}

# 问题
{用户问题}
```

### 4.3 函数调用示例

```
# 问题
我公司本月销售额是 125000 元，成本是 80000 元，税率是 15%。
请计算净利润。

# 可用操作
- calculate(数学表达式): 执行计算

# 执行流程
思考：需要先计算利润，然后扣除税金
行动：calculate("125000 - 80000")
观察：45000

思考：现在计算税金
行动：calculate("45000 * 0.15")
观察：6750

思考：最后计算净利润
行动：calculate("45000 - 6750")
观察：38250

最终答案：净利润是 38,250 元
```

## 5. 自我反思和迭代优化

### 5.1 Reflexion 模式

让模型自我评估输出，识别问题，然后改进。

**基础模板**：
```markdown
# 任务
{任务描述}

# 初次回答
请先给出你的初步答案。

# 自我评估
然后评估你的答案：
1. 是否完整回答了问题？
2. 是否有遗漏或错误？
3. 哪些地方可以改进？

# 改进版本
基于评估，给出改进后的答案。
```

### 5.2 批评家模式

```markdown
# 角色
你是一位严格的代码审查专家。

# 任务
审查以下代码并提供改进建议：

{代码}

# 审查维度
1. 代码质量
2. 性能问题
3. 安全漏洞
4. 可维护性
5. 最佳实践

# 输出格式
## 问题清单
- [ ] {问题1}
- [ ] {问题2}

## 改进建议
{具体建议}

## 改进后代码
{优化后的代码}
```

## 6. 分治法提示

### 6.1 复杂任务分解

将大任务分解为多个小任务，逐个解决。

**示例**：
```markdown
# 总体任务
设计一个完整的用户认证系统

# 分解步骤
请按以下步骤逐步完成：

## 步骤1：需求分析
分析认证系统需要哪些功能

## 步骤2：数据模型设计  
设计用户和认证相关的数据表结构

## 步骤3：API 设计
设计认证相关的 REST API 接口

## 步骤4：安全考虑
分析安全风险和防护措施

## 步骤5：代码实现
提供核心代码实现

每完成一步，请等待我的确认后再进行下一步。
```

### 6.2 渐进式细化

```markdown
# 第一版：高层设计
请先给出系统的整体架构和主要组件。

# 第二版：详细设计
基于架构，详细设计每个组件的接口和数据流。

# 第三版：实现细节
提供关键代码和实现细节。
```

## 7. 多轮对话提示

### 7.1 上下文维护

```markdown
# 对话历史
{之前的对话内容}

# 当前问题
{新的问题}

# 要求
- 基于对话历史理解上下文
- 如果信息不足，主动询问
- 保持对话的连贯性
```

### 7.2 主动澄清

```markdown
# 任务
你是一个需求分析师。

# 用户请求
{用户模糊的请求}

# 你的职责
1. 识别不清晰或有歧义的部分
2. 主动提出澄清问题
3. 等待用户回答后再继续

# 输出格式
## 理解
我对你的请求的理解是：{理解}

## 需要澄清
1. {问题1}
2. {问题2}
3. {问题3}

请回答以上问题，以便我更准确地帮助你。
```

## 9. 技术选择指南

| 场景 | 推荐技术 | 原因 |
|-----|---------|-----|
| 数学/逻辑推理 | 思维链 | 分步推理提高准确性 |
| 文档问答 | RAG | 提供准确信息来源 |

| 代码审查 | 自我反思 | 发现自身问题 |
