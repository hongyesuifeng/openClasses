## 1. 为什么需要工具调用？

### 1.1 大语言模型的局限

```
LLM 的能力边界
────────────────────────────────────────────────────────

✅ LLM 擅长的：
• 理解和生成文本
• 知识问答
• 推理和规划
• 代码生成

❌ LLM 做不到的：
• 获取实时信息（如当前天气、股价）
• 执行实际操作（如发送邮件、创建文件）
• 访问外部系统（如数据库、API）
• 进行数学计算（精确计算）

解决：让 LLM 能够调用工具！
```

### 1.2 工具调用的本质

```
工具调用流程
────────────────────────────────────────────────────────

┌─────────────────────────────────────────────────────┐
│                                                     │
│  用户: "帮我查一下北京现在的天气"                    │
│                                                     │
│  ┌─────────────────────────────────────────────┐   │
│  │ LLM 思考：                                   │   │
│  │ 我需要调用天气查询工具                       │   │
│  │ 参数：city = "北京"                         │   │
│  └─────────────────────────────────────────────┘   │
│                      │                              │
│                      ↓                              │
│  ┌─────────────────────────────────────────────┐   │
│  │ 工具调用：weather_api(city="北京")          │   │
│  └─────────────────────────────────────────────┘   │
│                      │                              │
│                      ↓                              │
│  ┌─────────────────────────────────────────────┐   │
│  │ 工具返回：                                  │   │
│  │ {"temp": 25, "condition": "晴", ...}       │   │
│  └─────────────────────────────────────────────┘   │
│                      │                              │
│                      ↓                              │
│  ┌─────────────────────────────────────────────┐   │
│  │ LLM 生成回复：                               │   │
│  │ "北京现在天气晴朗，气温25度"                 │   │
│  └─────────────────────────────────────────────┘   │
│                                                     │

## 2. Function Calling

### 2.1 基本概念

**Function Calling**：让 LLM 能够输出结构化的工具调用请求。

```
Function Calling 流程
────────────────────────────────────────────────────────

1. 定义工具
┌─────────────────────────────────────────────────────┐
│ {                                                   │
│   "name": "get_weather",                            │
│   "description": "获取指定城市的天气信息",           │
│   "parameters": {                                   │
│     "type": "object",                               │
│     "properties": {                                 │
│       "city": {                                     │
│         "type": "string",                           │
│         "description": "城市名称"                   │
│       }                                             │
│     },                                              │
│     "required": ["city"]                            │
│   }                                                 │
│ }                                                   │
└─────────────────────────────────────────────────────┘

2. 发送给模型
用户消息 + 工具定义 → LLM

3. 模型输出
┌─────────────────────────────────────────────────────┐
│ {                                                   │
│   "tool_calls": [{                                  │
│     "name": "get_weather",                          │
│     "arguments": "{\"city\": \"北京\"}"             │
│   }]                                                │
│ }                                                   │
└─────────────────────────────────────────────────────┘

4. 执行工具并返回结果
```

### 2.2 OpenAI Function Calling 示例

```python
import openai

# 定义工具
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取指定城市的天气信息",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "城市名称"
                    }
                },
                "required": ["city"]
            }
        }
    }
]

# 调用模型
response = openai.chat.completions.create(
    model="gpt-4",
    messages=[
        {"role": "user", "content": "北京今天天气怎么样？"}
    ],
    tools=tools
)

# 检查是否需要调用工具
if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    print(f"工具名称: {tool_call.function.name}")
    print(f"参数: {tool_call.function.arguments}")
    # 输出：
    # 工具名称: get_weather
    # 参数: {"city": "北京"}
```

## 3. ReAct 范式

### 3.1 ReAct 框架

**ReAct = Reasoning + Acting**

```
ReAct 循环
────────────────────────────────────────────────────────

┌─────────────────────────────────────────────────────┐
│                                                     │
│   Thought (思考)                                    │
│      │                                              │
│      ↓                                              │
│   Action (行动)                                     │
│      │                                              │
│      ↓                                              │
│   Observation (观察)                                │
│      │                                              │
│      ↓                                              │
│   Thought (再次思考)                                │
│      │                                              │
│     ...                                             │
│      │                                              │
│      ↓                                              │
│   Final Answer (最终答案)                           │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 3.2 ReAct 示例

```
任务：找出《三体》的作者是谁，并告诉我他/她还写过什么书

────────────────────────────────────────────────────────

Thought 1: 我需要先查找《三体》的作者是谁
Action 1: search("三体 作者")
Observation 1: 《三体》是刘慈欣创作的长篇科幻小说...

Thought 2: 知道作者是刘慈欣，现在需要查找他的其他作品
Action 2: search("刘慈欣 作品列表")
Observation 2: 刘慈欣的主要作品有：《球状闪电》、《流浪地球》...

Thought 3: 我已经获得了所需信息，可以回答了
Final Answer: 《三体》的作者是刘慈欣。他的其他代表作包括
              《球状闪电》、《流浪地球》、《乡村教师》等。

────────────────────────────────────────────────────────
```

### 3.3 ReAct vs 普通工具调用

```
对比
────────────────────────────────────────────────────────

普通工具调用：
┌─────────────────────────────────────────────────────┐
│ User → LLM → Tool Call → Result → LLM → Answer     │
│                                                     │
│ 特点：单次调用，简单任务                             │
└─────────────────────────────────────────────────────┘

ReAct：
┌─────────────────────────────────────────────────────┐
│ User → LLM → Thought → Action → Observe →          │
│        Thought → Action → Observe → ... → Answer   │
│                                                     │
│ 特点：多轮循环，复杂任务，有推理过程                  │
└─────────────────────────────────────────────────────┘

ReAct 优势：
• 能处理复杂多步骤任务
• 推理过程可解释
• 能根据中间结果调整策略
```

### 4.2 SKILL.md 定义

```markdown
# Web Search Skill

## 描述
搜索互联网获取实时信息

## 触发条件
当用户询问以下内容时触发：
- 实时信息（天气、新闻、股价）
- 最新事件
- 需要网络搜索的问题

## 输入参数
- query: 搜索关键词 (必需)
- num_results: 返回结果数量 (可选，默认5)

## 执行脚本
```bash
python skills/search.py --query "${query}" --num ${num_results}
```

## 输出格式
返回搜索结果的摘要列表
```

### 4.3 工具调用流程

```
OpenClaw 工具调用完整流程
────────────────────────────────────────────────────────

1. 用户输入
   "帮我查一下明天北京的天气，如果有雨就提醒我带伞"

2. 意图分析
   ┌─────────────────────────────────────────────────┐
   │ LLM 分析：                                       │
   │ - 需要查询天气 → weather skill                  │
   │ - 需要设置提醒 → reminder skill                 │
   └─────────────────────────────────────────────────┘

3. 规划执行
   ┌─────────────────────────────────────────────────┐
   │ Step 1: 调用 weather skill                      │
   │ Step 2: 分析结果是否下雨                        │
   │ Step 3: 如果下雨，调用 reminder skill           │
   └─────────────────────────────────────────────────┘

4. 执行工具
   weather_skill(city="北京", date="tomorrow")
   → {"condition": "rain", "probability": 0.8}

5. 结果处理
   ┌─────────────────────────────────────────────────┐
   │ LLM 判断：明天有 80% 概率下雨                    │
   │ 需要设置提醒                                    │
   └─────────────────────────────────────────────────┘

6. 执行后续工具
   reminder_skill(message="明天可能下雨，记得带伞",
                  time="明天早上8点")

7. 生成回复
   "我已经查到明天北京有80%的概率下雨，
    已为你设置提醒：明天早上8点提醒你带伞。"
```

## 5. MCP 协议

### 5.1 什么是 MCP？

**MCP (Model Context Protocol)**：Anthropic 提出的工具调用标准协议。

```
MCP 架构
────────────────────────────────────────────────────────

┌─────────────────────────────────────────────────────┐
│                   MCP Host                          │
│              (Claude / OpenClaw)                    │
│                                                     │
│  ┌─────────────────────────────────────────────┐   │
│  │              MCP Client                      │   │
│  │         (管理连接和通信)                      │   │
│  └─────────────────────────────────────────────┘   │
│                        │                            │
│         ┌──────────────┼──────────────┐            │
│         ↓              ↓              ↓            │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐      │
│  │MCP Server│   │MCP Server│   │MCP Server│      │
│  │ 文件系统  │   │ 数据库   │   │ Web搜索  │      │
│  └──────────┘   └──────────┘   └──────────┘      │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 5.2 MCP vs Skills

```
对比
────────────────────────────────────────────────────────

MCP:
• 标准化协议
• 跨平台兼容
• 适合外部工具集成

Skills:
• OpenClaw 原生

### 6.2 执行策略

```
执行策略
────────────────────────────────────────────────────────

1. 顺序执行
   A → B → C → D
   适用：有依赖关系的任务

2. 并行执行
   A ┐
     ├→ 汇总
   B ┘
   适用：独立的任务

3. 条件执行
   if A的结果 == X:
       执行 B
   else:
       执行 C

4. 循环执行
   for item in list:
       执行 A(item)
```

## 7. 安全与沙箱

### 7.1 安全考虑

```
工具调用安全风险
────────────────────────────────────────────────────────

⚠️ 风险：
• 恶意用户诱导执行危险操作

• 权限控制
• 参数验证
• 操作审计

## 关键要点总结

1. **工具调用**：让 LLM 突破能力边界，执行实际操作
2. **Function Calling**：结构化的工具调用接口
3. **ReAct 范式**：Reasoning + Acting，多轮循环执行
4. **OpenClaw Skills**：基于 Markdown 的轻量级工具定义
5. **MCP 协议**：标准化的工具调用协议
6. **安全沙箱**：隔离执行，保护系统安全
