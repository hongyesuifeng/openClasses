# AI Agent 评估与可控性学习实验计划

本实验研究如何约束、检查和复盘 Agent 的决策。建议以单回合卡牌行动选择为背景，用少量 JSON 状态和可用动作构造用例；先建立可复现的评估方法，再分析模型或提示方案的表现。

状态为计划中，尚未运行实验或产生性能结果。该方案是下一阶段的默认建议，可替换为其他感兴趣的学习问题。

## 学习问题

1. 一个动作符合输出格式，是否同时满足任务规则？
2. 如何区分模型选择错误、工具参数错误、执行异常和评估程序错误？
3. 如何保持相同输入、规则与判定方式，让两种方案的结果可以比较？

## 最小范围

输入包含玩家状态、可用资源、候选动作和必要的敌方信息。输出包含选择的动作、参数和简短理由。动作由固定集合提供，实验只验证单次选择与必要的状态变化。

所需材料是一份输入与输出说明、一组 JSON 用例、一个最小验证程序和一份结果记录。可以采用已熟悉的语言和现有运行环境，按需使用标准库。

学习实验放在当前工作区的新实验目录，例如 `domains/ai-agent/experiments/agent-evaluation/`。该路径是规划位置，当前尚未创建代码。实际游戏工程和子模块继续由各自项目维护。

## 用例设计

| 类型 | 数量 | 示例检查 |
| --- | --- | --- |
| 正常 | 3 | 合法动作、参数完整、理由与输入对应 |
| 非法动作 | 3 | 不存在的动作、资源不足、无效目标 |
| 边界 | 2 | 零资源、没有可行动作 |
| 异常 | 2 | 缺少输入字段、执行失败或超时 |

每个用例记录固定输入、允许的输出或判定条件，以及预期失败类别。策略质量如需评分，应提前定义效用规则或人工标注标准，区分“合法”与“策略较好”。

## 评估指标

- 格式有效率：输出满足既定字段、类型与动作集合的比例。
- 动作合法率：满足资源、目标和状态规则的比例。
- 任务正确性：按事先定义的判定规则评估，保留该规则的依据。
- 效率：记录决策次数或工具调用次数；接入真实模型后再记录实际耗时与用量。
- 失败分类：格式、规则、执行、模型选择或评估程序问题。

保留每个用例的输入、输出、判定结果和失败原因。汇总结果时同时报告用例数量与类型，避免只给出一个总分。

## 执行步骤与验收

- [ ] 阅读 [智能体性能评估](../../domains/ai-agent/courses/Hello-Agents/part3-advanced/ch12-evaluation/README.md) 和 [slayDemo 复盘](../../domains/game-engine/godotProjects/slayDemo/docs/project-retrospective.md) 中的验证方法。
- [ ] 写一页评估说明，明确任务、合法动作、指标和失败分类。
- [ ] 完成 10 个固定用例及判定规则。
- [ ] 用预设输出验证正常、非法和异常路径，确认评估程序能识别问题。
- [ ] 在同一用例集上比较至少两种方案，记录差异及可能原因。
- [ ] 有可用模型配置时，再开展真实模型实验并分别记录结果。
- [ ] 用结构化日志复现至少一个失败，并解释问题属于哪个环节。
- [ ] 总结适用条件、局限和可供实际项目采用的规则。

离线模拟用于验证评估程序和约束机制；模型能力结论需要真实模型运行记录。验收重点是用例可复现、判定依据明确，以及能够解释失败和方案差异。
